# GOAT Arena dataAnalysis

이 폴더는 `03_SUB_DIVISION_RANKING_SYSTEM_PAYBACK.md`와 손익 시뮬레이션에서 운영자가 첫 달에 반드시 실측해야 하는 값을 관리한다. MongoDB 컬렉션 이름도 `dataAnalysis`로 고정한다.

## 운영 원칙

- `METRIC_DEFINITION`: 무엇을 측정할지 정의한다. 값 자체가 아니다.
- `ASSUMPTION`: 출시 전 시뮬레이션에 사용한 임시 상수다. 첫 달 실측 후 재검토한다.
- `OBSERVATION`: 월·주 단위 실제 관측값이다. 원본 결제·학습권·대결 장부를 대체하지 않는다.
- `POLICY_SNAPSHOT`: 특정 정책 버전으로 집계한 결과를 보존한다.
- 첫 달 종료 후 표본 100건 이상인 주요 전환 이벤트부터 시뮬레이션 가정을 교체한다. 표본이 부족하면 가정값을 실제값처럼 확정하지 않는다.
- 가격 또는 페이백 구간 변경은 새 `SubscriptionPolicyVersion`으로 발행한다. 진행 중인 `AccessCycle.policySnapshot`은 바꾸지 않는다.
- 페이백 미달 후 재결제하는 이용자에게는 새 가격·페이백 구간을 결제 전에 고지하고 확인 시각을 남긴다.

## DB와 캐시 경계

DB에 반드시 남길 데이터:

- 결제, 환불, 페이백 심사·지급 결과
- `AccessCycle` 잔액과 불변 학습일 장부
- Arena GP·티어·티어 내 순위의 권위 상태와 변경 원장
- 대결 결과, 이의, 무결성 상태, 정책 버전
- 생년월일·본인확인 상태·중복 계정 검토 알림
- 월별 관측값과 그 표본 수

짧은 TTL 캐시로 계산해도 되는 데이터:

- 티어별 상위 20명과 내 주변 순위 조회 결과
- Arena 대시보드용 합성 카드
- 활성 정책 읽기 결과(정책 ID와 버전 포함)
- 관리자 분석 차트용 집계 결과
- 학교·교육과정 같은 변경 빈도가 낮은 참조 데이터

캐시만 남겨서는 안 되는 데이터:

- 학습일 잔액, 페이백 자격, GP 교환 결과
- 로그인·제재·Division 권한
- 결제 및 계좌 본인확인 결과
- 관리자 경고와 동일인 중복 탐지 결과

캐시는 서버 재시작 시 사라져도 복구 가능해야 하며, 권위 데이터의 변경이 성공한 뒤 관련 캐시 키를 무효화한다.

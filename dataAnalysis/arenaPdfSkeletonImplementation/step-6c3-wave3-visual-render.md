15개 문항을 `visual-preview-wave3.html`에서 모두 실제 생성한 뒤 GOAT Arena 1대1과 동일한 MathJax·SVG 렌더 경로로 한 문항씩 확인했다. 그래프, 좌표기하, 사물함 배치, 타일 조각이 모두 문항 본문에 표시되었다. `A_{3}`, `B_{3}`, `C_{3}`, `a_{4}`, `a_{7}`, `L_{13}`, `e^x`, `\sin^3x`는 평문이 아니라 실제 첨자·위첨자 수식 노드로 생성되었다.

## 발견 및 수정

원 도형에 기존 가로·세로 좌표축 배율이 다르게 적용되어 2016년 10월 가형 28번의 원이 밑변과 교차해 보이는 문제가 있었다. 원이 포함된 세 도형에 동일 축척을 적용했으며, 재검수에서 원의 최하점과 밑변 사이 픽셀 간격은 `0`이었다.

문제 본문은 MathJax를 사용했지만 SVG 내부 함수명·점 이름은 일반 `<text>`였기 때문에 `_3`이 첨자로 보이지 않았다. SVG 내부 수학 라벨을 MathJax가 처리하는 `foreignObject`로 변경하고, 중첩 MathJax SVG에 운영 화면의 바깥 SVG 크기 규칙이 잘못 적용되지 않도록 CSS 선택자를 직계 자식으로 제한했다.

2017년 9월 나형 30번 검산 해설의 `b=22/3` 문자열 조합 오류도 `b=4/3` 수식으로 바로잡았다.

미리보기 HTML을 `file://`로 직접 열면 렌더러의 `/public/js/...` 절대경로가 디스크 루트를 가리켜 그래프가 비어 있었다. 프로젝트 기준 상대경로 `../../public/js/...`로 변경하고 빌드 단계에서 실제 파일 존재 여부를 검사하도록 보강했다. 같은 산출물은 파일 직접 열기와 로컬 HTTP 미리보기에서 모두 동일한 렌더러를 사용한다.

함수식과 곡선 이름을 그래프 선 위에 직접 배치하던 방식을 제거했다. `y=x`, `y=|e^x-2|`, `y=g(x)`, `y=h(x)`, `y=16\sin^3x-2\sin x`, 두 조각함수 가지 이름, `y=f(x)`의 8개 라벨을 플롯 바깥 상단 범례 띠로 이동했다. 점 라벨 31개는 도형 중심의 반대 방향으로 자동 배치하고 수식에는 불투명한 흰 배경, 일반 문자에는 흰 외곽선을 적용했다. 브라우저 감사에서 범례 영역 이탈과 점 원점 침범은 모두 0개였다.

## 판정

Wave 3 시각형 15종은 생성기 검산, 실제 렌더, 수식 구조, 배치 경계 검수를 모두 통과했다. 전체 200개 격리 스켈레톤도 문항별 200 seed, 총 40,000회 이중 검산을 다시 통과했다. 이 결과는 구현 가능성 검증용이며 GOAT Arena 1대1 운영 출제에는 아직 연결하지 않았다.

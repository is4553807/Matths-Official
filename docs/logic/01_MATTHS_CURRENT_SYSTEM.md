# Matths 현행 시스템

> 기준 스냅샷: 2026-08-03  ·  범위: 현행 구현 설명
>
> 이 문서는 현행 서비스의 인증, 학습, 평가, MMR, 운영 기능을 설명한다. GOAT Arena의 Division 정책은 정의하지 않으며, Division 관련 규칙은 문서 인덱스에서 해당 문서를 따른다.

> **GOAT Arena 데이터 경계**
>
> 이 문서의 `MMR`, MMR 표시 티어, MMR 랭크 포인트와 주간 순위는
> 매주 일요일 사설 모의고사 및 배치고사에서 계산되는 **주간 실력 시스템**이다.
>
> GOAT Arena 1대1 경기에서는 다음 값을 별도로 사용한다.
>
> ```text
> Arena 상태
> = Arena 랭크
> + Arena 랭크 내 순위
> + Arena GP
> ```
>
> 모든 일반 1대1 및 복수전은 MMR을 상대 선정, 승패 판정, 스왑 또는 정산에 사용하지 않는다.
> 도전자가 이겼을 때만 두 사용자의 Arena 랭크·순위·GP를 통째로 교환하며,
> 방어자가 이기면 Arena 상태는 교환하지 않는다.
>
> MMR은 배치고사와 매주 일요일 공식 모의고사 정산에서만 변경된다.
> 일요일 공식 모의고사로 갱신된 MMR은 Unranked·Ranked 성과와 함께
> [`08_FINAL_RANKING_SYSTEM.md`](./08_FINAL_RANKING_SYSTEM.md)의 Final Rating 계산에 사용한다.
> MMR은 Arena GP를 직접 증감시키지 않는다.

## 0.1 GOAT Arena 구독·재진입 정책 오버레이

현행 구현 설명과 별도로 다음 신규 정책을 적용한다.

### 학습권 소진

```text
Unranked:
availableLearningDays = 0
→ ACCESS_EXPIRED_LOCKED

Ranked:
availableLearningDays = 0
AND reservedLearningDays = 0
AND lockedLearningDays = 0
AND noPendingSettlement
→ MAIN_DEMOTED_TO_SUB
→ SUB_ACCESS_EXPIRED_LOCKED
```

잠기는 기능:

- GOAT Arena 공격·방어·복수전
- 주간 공식 모의고사
- Weekly Mock Bonus
- 공식 Skill MMR 갱신
- 활성 Final Ranking 참여

사용자는 자신의 마지막 전적·랭크 스냅샷과 결제 화면만 확인할 수 있다.

무료 Arena 모드는 운영하지 않는다.

### 패키지 구매 조건

```text
availableLearningDays > 0
→ 새 패키지 즉시 구매 불가

availableLearningDays = 0
AND reservedLearningDays = 0
AND lockedLearningDays = 0
AND noPendingSettlement
→ 새 패키지 구매 가능
```

진행 중 경기의 예치분과 미정산 상태가 남아 있으면 정산 완료 뒤 구매할 수 있다.

### 결제 시각과 첫날 처리

기준 시간대는 `Asia/Seoul`이다.

```text
결제 시각 < 20:00
→ 결제 당일을 첫 학습일로 계산
→ 활성화 시 1일 즉시 소비

결제 시각 >= 20:00
→ 결제 당일은 무료 활성화 유예
→ 당일 학습권 차감 없음
→ 다음 00:00에 첫 1일 소비
```

앱에는 다음처럼 표시한다.

```text
20:00 이전 결제
→ 오늘 이용 중 · 잔여 학습권 28일

20:00 이후 결제
→ 오늘은 차감되지 않음 · 00:00부터 1일차
```

### Ranked 사용자의 이용 만료·재구독

Ranked 사용자의 사용 가능·초대 예약·경기 예치 학습일수가 모두 0이고 미정산 경기가 없으면 Ranked 이용이 만료되고 GOAT Arena가 잠긴다. 이후 처리는 `04_MAIN_DIVISION_RANKING_SYSTEM.md`의 Ranked 만료·재구독 규정을 따르며, 직전 Ranked 상태는 재구독 배치 계산을 위해 보존한다.

만료 순간 Ranked 전체 정확한 순위 `p`, 활성 참가자 수 `N`을 저장하고 `mainPercentile = 1 - (p - 1) / (N - 1)`로 계산한다. 참가자가 한 명이면 1.0이다. Unranked 기준은 `0.58 + 0.42 × mainPercentile`이며, 티어 구간·0~99 GP·정확한 Unranked 전체 순위 공식은 `04_MAIN_DIVISION_RANKING_SYSTEM.md` 15장을 따른다.

```text
학습권 만료
→ Ranked 이용 만료
→ GOAT Arena 이용 잠금

만료 후 72시간 이내 결제
→ 배치 시험 없음
→ Ranked-to-Unranked Rank Convert
→ 강등된 Unranked 랭크에서 새 페이백 경쟁 시작

만료 후 72시간 초과 결제
→ 재구독 랭크 결정전
→ Unranked 랭크 결정
→ 정상 갱신 변환 랭크보다 반드시 낮게 배치
```

`재구독 랭크 결정전`은 앱에서 `랭크 복귀전`으로 표시한다.

이 시험은 새 시즌의 `시즌 배치고사`와 다른 시험이다.

### 주간 모의고사

활성 29일 학습권 패키지 사용자 또는 활성 Matths 주간 공식 모의고사 이용권 사용자만 주간 공식 모의고사를 볼 수 있다. Matths 주간 공식 모의고사 이용권은 배치고사와 GOAT Arena를 열지 않는다.

- 정상 응시: Weekly Mock Bonus +30
- 미응시: Bonus 0
- 학습권 만료 사용자: 시험 응시 불가, Bonus 0

### Ranked 상점 정책 오버레이

Ranked 전용 상점 정책의 권위 원본은 [`12_SHOP.md`](./12_SHOP.md)다. 상점은 `MAIN`이면서 `PAID_ACTIVE`인 사용자만 이용하고 `availableLearningDays`만 사용한다. 예약·경기 예치 학습일수는 구매에 사용할 수 없으며 구매 뒤 최소 1일을 남긴다.

`방어 일정 보호권`은 문제 팩 열람 전 의무 방어 경기를 `INSURED_CANCELLED`로 끝내는 예외다. 승패·Arena 상태 교환·복수전 권리는 만들지 않고, 양측 기존 예치분 반환과 공격자 1일 보상·시스템 1일 소각을 한 트랜잭션에서 처리한다.

상점의 확정값은 가속 요청 우선 처리, 스타일 효과의 시즌 종료 만료, 분석 5분·최대 2회 재시도 뒤 자동 반환, 방어 편의 기능 공통 7일 쿨다운이다. 시즌 종료 10일 이내 구매한 시즌 장식은 다음 시즌까지 한 번 이월한다. `INSURED_CANCELLED`는 공식 실적에서 제외하지만 최근 상대 제외와 어뷰징 탐지에는 포함한다.

### 일요일 공개 경계

```text
일요일 14:00
→ Unranked·Ranked 신규 경기 신청·초대 수락·복수전 신청·준비·시작 차단

일요일 15:00
→ GOAT Arena와 공개 Final Ranking 동결

월요일 00:00
→ 새 MMR·Bonus·Final Ranking 일괄 공개
→ GOAT Arena 재활성화
```

## 1. 시스템 구조와 실행 흐름

### 1.1 기술 구성

- Node.js + Express 5.2.1
- EJS 6.0.1 서버 렌더링
- MongoDB + Mongoose 9.7.4
- `express-session` 기반 웹 세션
- 자체 HMAC 서명 Bearer 토큰 기반 모바일/API 인증
- `bcrypt` 12 rounds 비밀번호 해시
- `multer` 파일 업로드
- `nodemailer` Gmail SMTP 메일 발송
- `js-yaml` 2022 개정 교육과정·학교 데이터 로딩
- 브라우저 순수 JavaScript 기반 타이머, 자동 저장, 그래프, 문제 풀이 UI

### 1.2 서버 부팅 순서

```text
환경 변수 로드
  → Express/EJS/정적 파일/본문 파서 구성
  → 세션 미들웨어 구성
  → 공통 사용자·코치 메시지 locals 구성
  → /api/v1 API 라우트 연결
  → / 웹 라우트 연결
  → 중앙 오류 처리기 연결
  → MongoDB 접속
  → 승인된 커뮤니티 코치 문구 캐시 갱신
  → 사설 모의고사 스케줄러 시작
  → HOST:PORT 리스닝
```

- 정적 파일은 `public`에서 제공한다.
- 폼과 JSON 본문을 모두 파싱한다.
- 기본 포트는 `8000`, 기본 호스트는 `0.0.0.0`이다.
- 세션 비밀키는 `SECRET` 환경 변수에서 읽는다.
- 공통 렌더링 컨텍스트에 현재 사용자와 코치 모드에 맞춘 문구가 들어간다.
- API 오류는 JSON으로, 웹 오류는 웹 응답으로 처리하며 예상하지 못한 오류의 내부 정보는 노출하지 않는다.

### 1.3 계층별 책임

| 계층 | 책임 |
|---|---|
| `server.js` | 부팅, 공통 미들웨어, DB 접속, 라우팅, 오류 처리, 스케줄러 |
| `routes/matths-routes.js` | 웹 페이지 및 웹용 JSON 엔드포인트 선언, 인증·관리자·업로드 미들웨어 결합 |
| `routes/api-routes.js` | `/api/v1` 모바일/외부 API 선언 |
| `controllers/matthsController.js` | 웹 입력 정규화, 서비스 호출, 페이지 렌더링/리다이렉트/플래시성 세션 상태 |
| `controllers/apiController.js` | API 입력 검증, 인증 토큰 발급, JSON 응답 |
| `middleware/*` | 웹/API 인증, 관리자 권한, 세션 재검증, 업로드 제한 |

서버가 권위 원본이다. 브라우저의 타이머, 정답 표시, 자동 저장, UI 비활성화는 편의 기능이며, 최종 권한·마감·채점·MMR·계정 상태는 서버가 다시 판정한다.

## 0.2 2026-08-02 상품·접속시간·규정·계정 삭제 오버레이

### Matths 주간 공식 모의고사 이용권

- 초기 월 가격은 5,000원이며 관리자 화면에서 새 가격 정책 버전을 즉시 적용할 수 있다.
- Matths 주간 공식 모의고사만 허용한다.
- 배치고사, GOAT Arena 입장 권한과 공식 랭크전은 허용하지 않는다.
- 주간 공식 모의고사 결과로 MMR을 계산해 DB에 저장한다.
- 주간 공식 모의고사 4회 이상 기록 뒤 학습권 패키지로 변경해 배치고사를 완료하면 기존 MMR과 배치 결과를 가중 보정하고 `placement-calibration` 이력을 남긴다.
- `/pricing`에는 무료, Matths 주간 공식 모의고사 이용권, 29일 학습권 패키지를 3열로 비교 표시한다. 무료 사용자는 시각화 개념 학습과 평가센터 유형별 문제 풀이만 이용하고 배치고사·주간 공식 모의고사·GOAT Arena·최종 종합 랭킹은 이용하지 못한다.
- 비로그인 상태의 모든 상품 CTA는 회원가입으로 연결하고, 로그인 상태의 두 유료 상품은 `본인 결제`, `부모님에게 결제 요청하기` 진입 버튼을 각각 표시한다. 후속 결제 화면과 PG 승인은 아직 구현하지 않는다.

### 29일 학습 패키지

- 초기 가격은 29,000원이고 정기권 학습 가능 일수와 페이백 점수 초깃값은 각각 29일·29점이다.
- 두 값은 독립된 장부다. KST 일일 이용 차감은 정기권 학습 가능 일수에만 적용하며 페이백 점수를 그 값에서 계산하거나 자동 동기화하지 않는다.
- Unranked 페이백의 학습 조건은 해당 29일 이용 주기 전일 학습이다. 하루라도 학습 기록이 빠지면 그 주기의 전일 학습 조건을 충족하지 못한다.
- 서버 시작 시 활성 `SubscriptionPolicyVersion`이 없으면 2026년 8월 2일(KST)을 기준일로 하는 기본 정책을 한 번만 생성한다.
- 관리자는 Arena 정책 화면에서 가격만 즉시 새 정책 버전으로 적용하거나, 가격·페이백 자격·점수 구간을 포함한 전체 Unranked 정책을 작성 중 상태로 만든 뒤 활성화할 수 있다.
- Unranked 공식 규정 페이지는 현재 활성 정책의 가격, 자격, 점수별 페이백 비율과 예상 금액을 DB에서 읽어 표로 표시한다.
- 규정 표의 최근 수정일은 정책 생성·활성화·수정·적용 시각 가운데 가장 최근 값을 한국시간 기준으로 표시하며 초기 기준일은 2026년 8월 2일이다.

### 누적 접속시간

- 로그인 상태의 보이는 탭만 60초 heartbeat를 전송한다.
- 서버가 90초 이내 연속 수신한 구간만 누적한다.
- 프로필, GOAT Arena 프로필과 관리자 사용자 상세에 시간 단위로 표시한다.

### 관리자 계정 상세

- 대상 계정의 역할이 관리자이면 가입일, 최근 로그인, 누적 접속, 역할, 계정 상태만 요약한다.
- 학습 진행, 배치·랭킹, 게시판 활동, 문의, 개별 알림과 사용자 대상 Direct Actions는 조회·표시하지 않는다.
- 계정 보안과 운영 감사에 필요한 계정 관리와 관리 작업 이력은 유지한다.

### GOAT Arena 설명 구조

- 메인 화면은 GOAT Arena의 목적, 5문항·10분 1대1, 두 Division의 차이만 짧게 설명한다.
- Unranked와 Ranked는 별도의 공식 규정 페이지를 사용한다.
- 각 규정 페이지는 규정 번호, 절, 접을 수 있는 세부 조항과 고정 목차를 제공한다.
- 사용자에게 학습일수를 경기에 맡기는 행위는 `예치`, 경기 성립 뒤 분리된 잔액은 `경기 예치 학습일수`로 설명한다. 반환·이전·소각과 함께 사용하며 사행성으로 오해할 수 있는 표현은 노출하지 않는다.

### 문제은행 운영 안내

- 서버에서 실행되는 JavaScript를 웹 관리자 화면에서 직접 저장·실행하는 기능은 제공하지 않는다. 수학식 생성·검산 엔진은 코드 배포로만 바꾼다.
- 관리자는 `/admin/problem-banks`에서 서버에 등록된 1대1 생성 유형의 사용 여부·배정 가중치·1~999 정답 범위·운영 메모를 조정하고, 공개 `U1~U9`·`R1~R9`에 연결된 내부 카탈로그별로 최소 5개씩 선택해 DRAFT 문제 데이터 버전을 저장·수정·자동 검산·적용할 수 있다.
- Arena 1대1의 방어자 앵커 `U1~U9`·`R1~R9`, 객관 정답률 등급·단원 구성·실측 보정은 `arenaOneOnOneDifficultyPolicy.js`와 `arenaAccuracyDifficultyPolicy.js`가 관리한다. 기존 `T1~T9`는 DB 카탈로그 호환용 내부 키다. 2016~2026 고3 전월 전국연합학력평가·모의평가 128개 수학 시험지의 전 문항 3,037건을 조사했고, 교육과정에 맞으며 정답률 등급이 확정된 1,628건만 런타임 분류 근거로 쓴다. 브론즈부터 골드는 기초 일반·일반·상위 일반, 플래티넘부터 준킬러, 마스터부터 킬러를 단계적으로 혼합하며 참가자 양쪽의 최근 공식 경기 5개 유형을 먼저 제외한다.
- 문제 데이터 활성화는 유형별 5회 자동 검산을 통과해야 한다. 신규 경기는 활성 버전을 읽고 `ArenaProblemPack.problemDataVersionId`와 콘텐츠 버전을 봉인하므로, 적용 뒤에도 진행 중 경기는 생성 당시 문제를 유지한다.
- MongoDB Change Stream이 문제 데이터 캐시를 즉시 비우고, 지원하지 않는 환경은 최대 15초 TTL 뒤 새 버전을 조회하므로 데이터 구성 변경에는 서버 재시작이 필요 없다. 새 생성 함수나 검산 코드 자체를 바꾸는 경우에는 정상 코드 배포가 필요하다.
- 운영자가 업로드하는 주간 공식 모의고사 자료는 기존 관리자 업로드 화면에서 관리하며, 생성기 코드 변경은 자동 검산과 회귀 검증을 거쳐 배포한다.

### 관리자 계정 삭제

- 익명 보존은 개인정보·로그인 정보·원본 업로드 파일을 제거하고 통계용 학습·시험·MMR·Arena 기록을 익명 ID로 보존한다.
- 모든 데이터 삭제는 사용자 계정과 연결된 학습·시험·랭킹·Arena·게시판 문서 및 원본 파일을 삭제한다.
- 관리자 화면에서 두 방식을 라디오 선택하고 `계정삭제` 확인 문구를 입력해야 실행된다.

### Unranked 복수전

- 일반 쟁탈전 정산 시 패자에게 원경기당 한 번의 복수전 권리를 만든다.
- `복수하기`는 2일을 예치하고 직전 상대를 자동 참가시키며, `경기 종료`는 권리를 영구 포기한다.
- 정상 승패와 한쪽 24시간 미완료는 Unranked 정산표를 적용한다.
- 양측 모두 24시간 안에 완료하지 않으면 Arena 상태는 유지하고 도전자가 복수전에 예치한 2일을 전부 소각한다.

## 2. 인증, 권한, 계정 수명주기

### 2.1 웹 세션 인증

로그인된 요청마다 다음을 다시 확인한다.

1. 세션에 저장된 사용자 ID로 실제 계정을 조회한다.
2. 계정 존재 여부와 접근 가능 상태를 확인한다.
3. 세션의 `tokenVersion`과 사용자 문서의 버전을 비교한다.
4. 이름, 이메일, 역할, 학년, 학교, 환경 설정 등 세션 스냅샷을 최신 DB 값으로 동기화한다.
5. 학년 자동 진급과 학습 스트릭 수명주기를 반영한다.
6. 정지·탈퇴·비활성화·토큰 무효화 상태면 세션을 파기하고 로그인 화면으로 이동시킨다.

비로그인 사용자가 보호된 GET 페이지에 접근하면 안전한 내부 경로만 `returnTo`로 저장한다. 외부 URL이나 프로토콜 상대 URL은 로그인 후 이동 대상으로 인정하지 않는다.

`isLoggedOut` 대상에 이미 로그인한 사용자가 접근하면 관리자는 `/admin`, 일반 사용자는 `/main`으로 이동한다.

### 2.2 관리자 판정

다음 중 하나면 관리자다.

- 사용자 역할이 `admin`.
- 사용자 이메일이 `ADMIN_EMAIL`과 일치.
- `ADMIN_EMAIL`이 없으면 폴백 이메일 `admin@lsbproduction.com`과 일치.

관리자 전용 라우트는 로그인과 관리자 판정을 모두 거친다.

### 2.3 API Bearer 토큰

API 토큰은 JWT 라이브러리가 아니라 자체 3구간 토큰이다.

```text
base64url(header).base64url(payload).base64url(HMAC-SHA256(signature))
```

- 헤더 `typ`: `MATTHS`
- payload: `sub`, `email`, `role`, `ver`, `iat`, `exp`
- 서명 비밀키: `API_TOKEN_SECRET`, 없으면 `SECRET`
- 기본 유효 기간: 30일
- 최소 허용 TTL: 60초
- 서명 비교: 상수 시간 비교
- 매 요청 시 사용자 존재·계정 접근 상태·`tokenVersion`을 다시 확인

비밀번호 변경, 역할·계정 상태 변경, 제재, 탈퇴 등에서 `tokenVersion`을 올리면 기존 API 토큰과 웹 세션이 무효화된다.

### 2.4 회원가입

공통 규칙:

- 실명: 2–40자, 문자/결합문자/공백/마침표/아포스트로피/하이픈 계열만 허용
- 닉네임: NFKC 정규화 후 2–30자, `<`와 `>` 거부
- 이메일: 형식 검증 후 소문자 정규화
- 생년월일: `YYYY-MM-DD`, 미래 날짜·유효하지 않은 날짜 거부
- 학년: 10, 11, 12, 13 (`13`은 N수생)
- 비밀번호: 최소 8자, UTF-8 기준 72바이트 이하
- API 가입은 추가로 문자와 숫자를 모두 요구
- 웹 가입은 비밀번호 확인 일치 요구
- 약관·개인정보 동의 필요
- 재학생 학교는 지역·학교 코드로 YAML 학교 목록에 실제 존재해야 함
- N수생은 학교를 생략하며 N수생 전용 게시판 권한을 사용
- 이메일과 정규화 닉네임의 중복을 금지
- 비밀번호는 bcrypt 12 rounds
- 약관/개인정보 버전: `2026-08-01`

생성되는 식별 정보:

- `realName`: 등록 실명
- `name`: 공개 닉네임
- `nameNormalized`: 중복 판정용 정규화 닉네임
- `anonymousNumber`: 커뮤니티 익명 표시에 쓰는 고정 6자리 번호
- `identityMatchHash`: 재학생의 실명·생년월일·고등학교 코드를 조합한 HMAC 해시

재학생의 실명·생년월일·고등학교가 모두 일치할 때만 관리자 중복 계정 검토 알림을 생성한다. 학교가 없는 N수생은 이 자동 비교에서 제외하며 자동 탐지만으로 계정을 정지하거나 페이백을 거절하지 않는다.

웹 가입 완료 후 세션을 재생성해 자동 로그인한다.

### 2.5 로그인·로그아웃

- 이메일 또는 닉네임으로 로그인할 수 있다.
- 이메일·닉네임과 비밀번호 불일치는 같은 일반 오류로 응답해 계정 존재 여부를 숨긴다.
- 비밀번호 해시는 기본 조회에서 제외되며 로그인 시 명시적으로 선택한다.
- 로그인 전 계정 접근 가능 여부와 수명주기를 확인한다.
- 성공 시 최근 로그인 시각을 저장하고 세션 고정 공격 방지를 위해 세션을 재생성한다.
- 안전한 내부 `returnTo`가 있으면 그곳으로, 없으면 관리자 `/admin`, 일반 사용자 `/main`으로 이동한다.
- 로그아웃은 세션을 파기한다.

### 2.6 비밀번호 변경

- 현재 비밀번호 확인 필수
- 새 비밀번호 최소 8자, 최대 72바이트
- 현재 비밀번호와 달라야 함
- 확인 입력과 일치해야 함
- bcrypt 12 rounds로 재해시
- 저장 후 `tokenVersion` 증가

### 2.7 비밀번호 재설정

두 가지 모드를 지원한다.

#### 6자리 코드 방식

- 6자리 난수 코드
- 10분 만료
- 60초 내 재전송 억제
- 새 코드를 만들면 이전 `pending`/`verified` 코드는 무효화
- 최대 5회 실패 시 `locked`
- 원문 코드는 저장하지 않고 HMAC 해시 저장
- 검증은 상수 시간 비교
- 검증 성공 시 `verified`, 재설정 성공 시 `used`

#### 링크 방식

- 32바이트 랜덤 토큰의 hex 표현
- 10분 만료
- 활성·접근 가능 계정만 대상
- 성공 시 새 비밀번호를 bcrypt 12 rounds로 저장
- `tokenVersion` 증가
- 사용된 요청과 다른 열린 요청을 잠금/종료

운영 환경에서는 Gmail 설정 누락을 오류로 처리한다. 비운영 환경에서는 실제 전송 대신 확인 가능한 프리뷰를 반환할 수 있다.

### 2.8 학교와 공개 랭킹 신원

- 학교 변경은 서버 학교 목록으로 재검증한다.
- 랭킹 표시 신원은 `nickname` 또는 `realName`.
- `realName` 선택 시 등록 실명만 사용한다.
- 학교 데이터에는 지역, 코드, 학교명, 주소, 설립/학교 유형이 저장된다.

### 2.9 학년 자동 진급

- 한국 시간 기준으로 날짜를 계산한다.
- 학년 연도는 3월에 시작한다.
- 마지막 반영 학년도 이후 경과 연수만큼 학년을 올린다.
- 최대 내부 학년 값은 13이다.
- 같은 학년도에 중복 진급하지 않도록 연도 표식을 저장한다.

### 2.10 학습 스트릭

학습 기록 시 낙관적 동시성 비교·갱신을 최대 4회 시도한다.

- 오늘 이미 학습: 현재 스트릭 유지
- 마지막 학습일이 어제: 스트릭 `+1`
- 그 외: 스트릭 `1`
- 최장 스트릭은 현재 값과 비교해 갱신
- 단순 페이지 열람이 아니라 실제 인정되는 학습 제출에서 호출

로그인 시 마지막 학습일이 오늘/어제가 아니면 현재 스트릭을 0으로 정리한다.

### 2.11 계정 상태

주요 상태:

- `active`
- `inactive`
- `suspended`
- `withdrawn`

기간 정지는 만료 시 자동으로 활성화되고 `tokenVersion`이 올라간다. 관리자 경고는 0–999 범위이고, 비관리자 사용자가 3회 이상 경고를 받으면 자동 정지될 수 있다.

### 2.12 회원 탈퇴와 데이터 삭제

사용자 본인 탈퇴 조건:

- 현재 비밀번호
- 확인 문구 `탈퇴`
- 익명 통계 보존 동의

본인 탈퇴는 기본적으로 **익명 보존**이다.

- 비밀번호 재설정 코드, 알림, 닉네임 변경 요청, 문의 삭제
- 관리자 로그의 사용자 식별 상세 익명화
- 랭킹 프로필은 `datasetOnly`로 바꾸고 순위에서 제외
- 글·댓글은 숨김/익명 처리
- 코치 제안 작성자 익명화
- 사용자 PII를 무작위·무효 값으로 치환
- 학교는 광역 지역 수준만 남김
- 상태 `withdrawn`
- 토큰 버전 증가

관리자는 역할을 먼저 제거하지 않으면 본인 관리자 계정을 탈퇴할 수 없다.

관리자용 영구 삭제는 별도 정책이며, 요청 시 학습·시험·퀵 연습·사설 모의고사·랭킹·커뮤니티 데이터까지 제거한다. 익명 보존 탈퇴와 물리적 삭제를 같은 동작으로 취급하지 않는다.

## 3. 공통 수학 답안 처리

### 3.1 입력 정규화

답안 비교 전에 다음을 정규화한다.

- 소문자화
- 앞뒤 공백과 수학 TeX 래퍼 제거
- 유니코드 마이너스를 일반 `-`로 변환
- 곱셈·나눗셈 기호 통일
- `π`와 `pi` 통일
- TeX `\frac`, `\sqrt`, 세제곱근 표현 변환
- 암시적 곱셈 처리

### 3.2 수식 파서

허용 토큰:

- 숫자
- `sqrt`, `cbrt`, `pi`
- `+ - * / ^`
- 괄호

재귀 하강 파서가 다음 우선순위를 처리한다.

1. 괄호·상수·함수
2. 단항 `+/-`
3. 거듭제곱 — 우결합
4. 명시적·암시적 곱셈/나눗셈
5. 덧셈/뺄셈

### 3.3 동치 판정

- 쉼표 목록은 원소 순서를 보존해 재귀 비교한다.
- 수치식으로 안전하게 평가되면 허용 오차는 `max(1e-7, |expected| × 1e-7)`.
- 수치 평가가 불가능하면 정규화된 문자열의 완전 일치를 사용한다.
- 문제별 사용자 정의 검증기가 있으면 그것도 함께 통과해야 한다.

- 과정 진행률은 단원 평균, 단원 진행률은 개념 평균으로 계산한다.

1. 이미 `in-progress`인 개념
2. 완료되지 않은 첫 공통과정 개념
3. 나머지 완료되지 않은 개념

### 4.2 개념 진행률 공식

개념 진행률은 세 축으로 구성된다.

```text
주제 학습 완료      최대 30%
서로 다른 유형 정답 최대 60%
사용자 완료 체크    10%
합계               최대 100%
```

세부 규칙:

- 기본 요구 정답 유형 수는 5개다.
- 유형 게이트를 열기 전 사용자가 완료 체크를 해도 전체 진행률은 최대 90%다.
- 주제 진행률만으로는 최대 30%.
- 서로 다른 정답 유형 수가 요구치에 도달하면 유형 부분 최대 60%.
- 유형 게이트를 연 뒤 최초 완료 체크 시 100%.
- 완료 체크를 반복해 중복 보상하지 않는다.
- 진행률에 따라 `not-started`, `in-progress`, `completed`를 갱신한다.

평가를 통과해야 하는 과정/단원 화면에서는 학습 진행률이 높아도 평가 전 표시를 최대 95%로 제한할 수 있다.

### 4.3 실제 생성형 문제 지원 범위

현행 교육과정 카탈로그는 13과정 전체를 제공하지만, 개념 연습 문제 생성기와 정식 평가 템플릿은 다음 세 과목에 집중되어 있다.

- 대수: 18개 개념, 개념당 10개 유형
- 미적분 I: 20개 개념, 개념당 10개 유형
- 확률과 통계: 16개 개념 정의와 생성기

나머지 과정은 교육과정 탐색과 진행 구조에는 존재하지만 같은 수준의 생성형 문제/평가 커버리지를 갖지 않는다.

### 4.4 개념 시각화

- 대수: 지수·로그·삼각함수·수열 중심 SVG/Canvas 그래프, 슬라이더, 줌, 포인터 상호작용

## 5. 개념 연습, 오답 노트, 퀵 연습

### 5.1 개념 연습 문제 선택

- 세션당 최대 30문제
- 세션 만료 15분
- 아직 맞히지 않은 유형을 우선 선택
- 모두 경험했다면 후보 중 무작위 선택
- 최근 프롬프트 반복을 줄이기 위해 세션·복습 기준 최대 50개를 기억
- 오답 복습은 같은 유형을 우선하고, 불가능하면 안정 해시로 가까운 난이도를 선택
- 수치 변형 생성은 최대 16회 시도
- 고정 문제는 필요하면 재사용될 수 있음

생성 결과 검증:

- 문제 문장과 수학 입력 존재
- 정답·풀이·힌트 존재
- 객관식이면 선택지 유효
- 수치 값이 유한
- 시각화 데이터 유효
- 유형별 사용자 정의 검증 통과
- 최대 30회 생성 재시도

### 5.2 개념 연습 제출

제출 시:

1. 답안을 서버에서 동치 비교한다.
2. 총 시도·총 학습 시간·정답 수를 갱신한다.
3. 맞힌 경우에만 해당 문제 유형을 `correctProblemTypes`에 추가한다.
4. `ProblemAttempt`와 `LearningEvent`를 기록한다.
5. 틀리면 오답 복습 상태를 `pending`으로 만든다.
6. 학습 스트릭을 실제 활동으로 기록한다.

오답 복습 결과:

- 원문 문제를 다시 맞히면 `completed` 및 `corrected`.
- 다시 틀리면 다음 한국 날짜 00:00 이후로 `scheduled`.
- 복습 제출을 별도의 새 오답 카드로 중복 생성하지 않는다.

요구 유형 수를 채우기 전에는 사용자 완료 체크를 받아도 개념을 100%로 만들지 않는다.

### 5.3 오답 노트

- 퀵 연습 오답과 개념 문제 오답을 동기화한다.
- 문제별 최신 오답 상태를 기준으로 최대 500건을 검토한다.
- 페이지당 10건.
- 상태: `all`, `pending`, `scheduled`, `completed`.
- 정렬: 최신, 오래된, 난이도, 우선순위.
- 우선순위 정렬은 복습 예정 도래 여부 → 상태 → 최근성 순이다.
- 과목 필터와 검색을 지원한다.
- 개념 문제 오답은 생성형 변형 복습이 가능하다.
- 퀵 연습은 개념 생성기 기반 재시도 대상이 아니다.

### 5.4 퀵 연습

기본 규칙:

- 제한 시간 40초
- 2점 또는 3점 문항
- 8개 주제 × 3개 변형 = 24개 유형

주제:

1. 지수 법칙
2. 다항함수 미분
3. 부정적분 값
4. 삼각비
5. 등비수열 관계
6. 시그마 변환
7. 한쪽 극한
8. 조각함수 연속

문항 패턴은 2022–2026년 6월·9월 모의평가 첫 페이지의 유형 경향을 구조적으로 참고하되 문장을 복사하지 않는다.

문제 발급:

- 생성 답과 독립 계산 답이 일치하는지 최대 40회 검증
- 최근 3개 주제와 최근 2개 변형을 회피

제출:

- 서버 마감 이후면 `expired`

### 7.5 배치 점수 계산

스무딩 정확도:

```text
adjustedAccuracy = (correct + 1) / (total + 2)
```

핵심 역량:

```text
core = 0.55 × 전체 점수 백분위
     + 0.45 × 3점 문항 adjustedAccuracy
```

심화 역량:

```text
advanced = 0.50 × 4점 문항 adjustedAccuracy
         + 0.20 × 준킬러 adjustedAccuracy
         + 0.30 × 킬러 adjustedAccuracy
```

최종 배치 성능 점수:

```text
placementScore = 100 × (0.65 × core + 0.35 × advanced)
```

일관성:

- 쉬운 문항 오답과 어려운 문항 정답의 역전 쌍을 센다.
- 비교 가능한 쌍이 있으면 `1 - contradictions / comparisons`.
- 비교가 불가능하면 0.5.

추가 지표:

- 기초 안정성: 일반 문항 정확도 기반
- 실수 가능성: 쉬운 오답/어려운 정답 패턴 수
- 답변률
- 문항 시간 기록 커버리지

신뢰도:

```text
confidence = 0.40 × 답변률
           + 0.20 × 시간 기록 커버리지
           + 0.20 × 일관성
           + 0.20 × 추가 안정 지표
```

### 7.6 검증 시험 트리거

다음 이상 신호를 점수화한다.

| 조건 | 플래그 |
|---|---:|
| 총점 백분위 < 0.45인데 어려운 문항 2개 이상 정답 | +2 |
| 3점 원정확도 < 0.65, 4점 정확도 ≥ 0.75 | +1 |
| 쉬운 문항 오답·어려운 문항 정답 역전 | +2 |
| 어려운 문항을 예상 시간의 20% 미만에 정답 | +1 |
| 원점수가 40/50/60/70/80/90 중 하나와 2점 이내 | +1 |

합계가 2 이상이면 검증이 필요하다.

검증 시험:

- 이전에 보지 않은 고유 유형 4문항
- 준킬러 2 + 킬러 2
- 제한 시간 40분

검증 후:

```text
advancedFinal = 0.35 × 기존 advanced
              + 0.65 × 검증 정확도
```

- 배치 점수를 다시 계산한다.
- 검증에서 2문항 이상 정답이면 `confirmed`.
- 2문항 미만이어도 `unconfirmed`로 표시할 뿐 랭킹 프로필 생성은 완료한다.

이 확인 단계는 배치 위치를 보정하기 위한 절차다. 배치고사는 서버 기준 문항별 풀이시간·답안 변경·진행 흐름과 위 4문항 확인 시험까지만 사용하며, Arena 1대1 경기의 60초 필수 풀이 증거 업로드·운영자 추가 소명·경고·매치메이킹 제재를 적용하지 않는다. 배치 결과 자체는 상대 자산을 이전하거나 공식 1대1 승패를 확정하지 않으므로 별도 경쟁 부정행위 사건으로 만들지 않고, 초기 위치의 신뢰도는 확인 시험과 이후 공식 성적으로 보정한다.

### 7.7 시도 재개와 버전 처리

- 가장 최근 제출된 배치고사를 공식 결과로 사용한다.
- 진행 중 시도가 있으면 재개한다.
- 답이 하나도 없고 문제은행 버전이 오래된 시도는 현재 버전으로 새로 구성한다.
- 하나라도 답한 시도는 버전이 달라도 사용자 작업을 보존하고 재개한다.

### 7.8 최초 Unranked 배치 연결

검증 문항까지 끝난 최초 배치고사는 한 번만 Unranked 시작 상태를 만든다.

- 배치 결과의 초기 rating은 `INITIAL-PLACEMENT-BASELINE-V1` 기준으로 최초 Arena 티어와 해당 티어 내부 `0~99 GP`로 변환한다.
- 이 복사는 최초 생성 시에만 수행하며, 이후 GP의 권위 원본은 `ArenaStanding`이다.
- 이후 배치·주간 공식 모의고사에서 변경되는 Skill MMR이 Arena GP를 다시 덮어쓰지 않는다.
- `arenaPosition`은 전체 순위가 아니라 같은 티어 안의 순위다.
- Arena 티어 서열을 먼저 비교한 뒤 같은 티어에서는 GP 내림차순으로 정렬한다. 같은 배치 결과의 동점은 배치 점수 높은 순 → 전체 풀이시간 짧은 순 → 배치 MMR 높은 순 → 배치고사 실제 시작 시각 빠른 순으로 정하고, 그래도 같으면 안정적인 사용자 ID 순서를 사용한다.
- 결제 전 완료자는 `PAYMENT_REQUIRED`와 잠긴 순위를 보존한다.
- 결제 후 미완료자는 `SEASON_PLACEMENT_REQUIRED`를 유지한다.
- 활성 학습권과 완료된 배치고사가 모두 있을 때만 `PAID_ACTIVE`와 공식 순위·방어·주간 공식 모의고사·최종 종합 랭킹 권한을 활성화한다.
- 과거 완료자는 배치고사 대시보드를 다시 열면 같은 배치 기록으로 멱등 복구한다.
- 이전 연도 배치 기록은 현재 시즌 권한을 다시 열지 않으며, 만료·재구독 상태는 최초 배치 복구가 덮어쓰지 않는다.
- Unranked 학습권 만료 뒤 패키지를 재결제하면 기존 배치 결과를 재사용하지 않고 배치고사를 다시 완료해야 한다.

## 8. 주간 모의고사 MMR — GOAT Arena 1대1과 분리

### 8.1 현행 MMR 표시 티어 기준

이 장의 Bronze부터 Challenger까지의 명칭은 **현행 MMR 표시 티어**다.

GOAT Arena의 Arena 랭크와 이름이 같을 수 있지만 서로 다른 데이터다.

```text
현행 MMR 표시 티어
= 주간 모의고사 MMR에서 계산

GOAT Arena 랭크
= Arena 프로필의 별도 값
```

1대1 경기 결과로 이 장의 MMR, MMR 표시 티어, MMR 랭크 포인트, MMR 이력을 변경해서는 안 된다.

| 티어 | MMR | 추가 인구 조건 |
|---|---:|---|
| Bronze | 0–799 | 없음 |
| Silver | 800–924 | 없음 |
| Gold | 925–1024 | 없음 |
| Platinum | 1025–1119 | 없음 |
| Emerald | 1120–1209 | 없음 |
| Diamond | 1210–1329 | 없음 |
| Master | 1330–1439 | 상위 5% 조건 가능 |
| Grandmaster | 1440–1519 | 상위 1.5% 조건 가능 |
| Challenger | 1520 이상 | 상위 0.5% 조건 가능 |

### 8.2 초기 MMR

배치 점수 모집단의 평균과 모표준편차를 사용한다.

```text
z = (사용자 placementScore - 모집단 평균) / 모집단 모표준편차
initialMmr = round(clamp(1000 + 200 × z, 400, 1700))
```

모표준편차가 `0.01` 이하이면 초기 MMR은 1000이다.

백분위:

- 모집단 5명 미만: 0.5
- 그 외: `(나보다 낮은 수 + 0.5 × 동점 수) / 전체 수`

### 8.3 상위 티어 인구 제한

MMR 구간을 만족해도 랭킹 모집단 규모에 따라 상위 티어를 제한한다.

| 랭커 수 | Challenger | Grandmaster | 나머지 상위 |
|---:|---|---|---|
| 100 미만 | 없음 | 없음 | 최대 Master |
| 100–299 | 상위 1명 | 상위 3명 | 그 외 최대 Master |
| 300 이상 | 상위 0.5% | 상위 1.5% | 상위 5%까지 Master, 그 외 최대 Diamond |

### 8.4 MMR 표시용 랭크 포인트·디비전

여기서 `rankPoint`는 기존 MMR 화면 표시용 값이다.

```text
MMR rankPoint != Arena GP
```

- MMR `rankPoint`는 1대1에서 교환하지 않는다.
- Arena GP는 Skill MMR과 분리된 `ArenaStanding`에 저장한다.
- 도전자 승리 시 교환하는 GP는 Arena GP이며, 이 장의 MMR `rankPoint`가 아니다.

티어 범위 안의 상대 위치:

```text
rankPoint = floor(
  clamp((mmr - tierMin) / (tierMax - tierMin + 1), 0, 1) × 100
)
```

- Challenger의 상한 표시는 99.
- 디비전:

```text
division = max(1, 4 - floor(clamp(rankPoint / 100, 0, 1) × 4))
```

### 8.5 주간 실력값

실제 성능:

```text
actual = 0.70 × 총점 백분위
       + 0.20 × 심화 지표
       + 0.10 × 일관성
```

주간 심화 지표:

```text
advancedRaw = 0.50 × 4점 정확도
            + 0.20 × Q20·Q21 정확도
            + 0.30 × Q28·Q30 정확도
```

주간 일관성:

```text
consistency = 0.75 × 3점 정확도
            + 0.25 × 답변 완료율
```

### 8.6 기대 성능

최근 성능 수에 따라:

```text
0개: 최근 배치 성능
1개: 0.40 × 배치 + 0.60 × 최신
2개: 0.60 × 최신 + 0.40 × 두 번째
3개 이상: 0.50 × 최신 + 0.30 × 두 번째 + 0.20 × 세 번째
```

### 8.7 K값, 성장 보너스, 변화 제한

K값:

| 조건 | K |
|---|---:|
| 35일 이상 비활동 | 160 |
| provisional 또는 주간 참여 ≤ 2 | 200 |
| 주간 참여 ≤ 5 | 140 |
| 그 외 | 100 |

성장 보너스는 현재 실제 성능과 최근 평균의 차이로 계산한다.

| 상승 폭 | 보너스 |
|---:|---:|
| ≥ 0.20 | +12 |
| ≥ 0.15 | +8 |
| ≥ 0.10 | +5 |
| ≥ 0.05 | +2 |
| 그 외 | 0 |

변화 제한:

- provisional: ±100
- confirmed이며 주간 참여 6회 이상: ±55
- 그 외: ±70

최종 변화:

```text
delta = round(clamp(K × (actual - expected) + growthBonus, -limit, +limit))
```

### 8.8 결석 감점

- 첫 번째·두 번째 결석: 각 `-5`
- 세 번째 이후 결석: 각 `-10`

데이터셋 전용 프로필은 일반 랭킹 참여·결석 처리에서 제외한다.

### 8.9 강등 보호

- 현재 티어 최저점보다 20점 낮은 값을 강등 판정선으로 사용한다.
- 그 선 아래로 한 번 내려가면 보호 상태.
- 연속 두 번째 판정에서도 아래면 강등.
- Bronze는 강등 없음.

### 8.10 상태와 이력

- 주간 공식 시험 2회 전까지 `provisional`
- 2회부터 `confirmed`
- 최근 성능 최대 3개 유지
- 전체 MMR 이력 최대 100개 유지
- 같은 기준 시험에 대한 주간 계산은 이력 앵커로 중복 적용을 막는다.

### 8.11 주간 전체 갱신

1. 유효 참가자의 `actual`, 심화, 원점수 등을 계산한다.
2. 각 프로필에 새 MMR을 계산한다.
3. 새 MMR과 실제 성능 등으로 참가자를 정렬한다.
4. 모집단 상위 티어 제한을 적용한다.
5. 불참 프로필에 결석 감점을 적용한다.
6. 시험 시도와 `PrivateMockWeeklyResult`를 기록한다.
7. 전체 프로필을 MMR 내림차순, 현 MMR 도달 시각 오름차순으로 재정렬한다.
8. `overallRank`와 전체 대비 백분위를 저장한다.

저장 백분위는 `1 - index / count` 형태가 아니라 현재 구현상 `1 - (1-based rank - 1) / count` 계열의 순위 위치 의미로 사용되며, 1위가 최상단 값이 되도록 랭킹 서비스의 표시 백분위와 구분해서 해석해야 한다.

주간 전체 갱신은 MMR을 변경할 수 있는 공식 경로다.

주간 MMR 정산 뒤 별도의 `WeeklyFinalRankingCalculation` 작업이
갱신된 MMR과 Unranked·Ranked 스냅샷을 사용해 Final Rating을 계산한다.

```text
일요일 모의고사 정산
→ MMR 갱신
→ Sunday Division 입력 고정
→ Final Rating 공식 재계산
→ 공식 기준 결과 저장
→ 월요일부터 실시간 갱신 재개
```

같은 시험의 원점수는 Final Rating에 별도로 다시 더하지 않는다.
이 흐름은 1대1 Match 정산과 같은 트랜잭션이나 서비스에서 실행하지 않는다.

## 9. 현행 MMR 랭킹 — Arena 랭킹과 분리

### 9.1 개인 랭킹 정렬

활성 사용자마다 가장 최근의 검증된 배치 결과와 랭킹 프로필을 결합한다.

정렬 우선순위:

1. rating/MMR 내림차순
2. 최신 성능 내림차순
3. 최근 성능 평균 내림차순
4. 심화 지표 내림차순
5. 배치 총점 내림차순
6. 현재 MMR 도달 시각 오름차순
7. 풀이 시간 오름차순

완전히 같은 동점 키에는 경쟁 순위 방식을 적용한다. 표시 이름은 사용자 선택에 따라 닉네임 또는 실명이다.

### 9.2 학교·도시 랭킹

집계값:

- 평균 rating — 반올림
- 평균 배치 점수
- 참가자 수
- 최고 개인 성과

정렬:

1. 평균 rating 내림차순
2. 참가자 수 내림차순
3. 최고 성과 내림차순

반환 범위:

- 전체 개인 Top 100
- 학교 내 Top 100
- 학교 Top 100
- 도시 Top 100
- 현재 사용자의 전체·학교 개인 위치
- 현재 학교·도시 위치

### 9.3 MMR 표시값과 Arena 상태 분리

주간 모의고사 화면의 MMR 표시 티어는 MMR 티어 설정을 사용한다. 이 값은 GOAT Arena 랭크·순위·GP와 분리하며 서로 덮어쓰거나 같은 필드 의미로 사용하지 않는다.

### 9.4 Final Ranking과의 관계

현행 이 장의 개인·학교·도시 랭킹은 MMR 기반 기존 랭킹이다.

새 Final Ranking은 이를 덮어쓰지 않고 별도 결과로 저장한다.

```text
Final Rating
= 갱신된 Skill MMR
+ Division 기본점수
+ Unranked·Ranked 성장점수
+ Unranked·Ranked 위치점수
```

가장 최근 필수 일요일 공식 모의고사를 완료한 사용자만 활성 Final Ranking에 포함한다.

Final Ranking은 평상시 Unranked·Ranked Arena 정산 직후 실시간으로 재계산한다.
Division 기본점수와 성장·위치점수는 누적하지 않고 매번 공식으로 덮어쓴다.

매주 일요일 14:00부터 Unranked·Ranked의 새 공식 경기 신청·수락·준비·시작을 모두 차단한다. 15:00부터 월요일 00:00까지 두 Division의 모든 공식 경기 쓰기를 잠그며,
이 시간에는 Division 입력을 고정한 뒤 MMR과 공식 Final Ranking을 계산한다.

매년 12월 31일에는 Final Ranking 시즌을 종료·보관하고,
1월 1일 새 시즌의 Division 성장 기준점을 생성한다.

정확한 공식과 데이터 모델은
[`08_FINAL_RANKING_SYSTEM.md`](./08_FINAL_RANKING_SYSTEM.md)를 따른다.

## 10. 사설 모의고사

### 10.1 GOAT Arena 일요일 잠금 경계

기존 사설 모의고사의 일요일 시험 시간대와 겹치는 동안
GOAT Arena Unranked·Ranked 공식 경쟁을 잠근다.

```text
일요일 15:00 KST
→ Unranked·Ranked 잠금

월요일 00:00 KST
→ Unranked·Ranked 잠금 해제
```

새 매치 신청·수락·준비·시작 cutoff는 일요일 14:00으로 고정한다.

15:00까지 정산되지 않은 공식 경기는 `HELD`로 보내고
Sunday Division 스냅샷에 반영하지 않는다.

### 10.1 시험 슬롯과 시간

기본 공식 슬롯:

| 슬롯 | 요일·시각 |
|---|---|
| A | 일요일 15:00 |
| B | 일요일 18:00 |
| C | 일요일 21:00 |

- 시험 시간: 100분
- 로비 입장: 시작 10분 전
- 운영 확인 슬롯: `CUSTOM`, 공개 날짜와 시각은 운영자가 직접 지정
- 일반 A/B는 각 시험 종료 시각 이후 닫힘
- C는 종료 후 1분까지 집계 대기
- 공식 주간 랭킹 발표: 일요일 23:00
- 리뷰·보관 전환: 일요일 23:00
- CUSTOM은 정식 주간 랭킹·GP·자동 아카이브에서 제외하며 운영 확인용의 별도 빠른 수명주기를 사용

### 10.2 시험 상태

```text
scheduled
  → open
  → locked
  → aggregating
  → ranked
  → archived
```

- `scheduled`: 공개 전
- `open`: 응시 가능
- `locked`: 새 응시와 수정 차단
- `aggregating`: 채점·지표·주간 대표 선택·MMR 처리
- `ranked`: 결과와 공식 랭킹 계산 완료
- `archived`: 문제·결과 열람 정책에 따라 보관

스케줄러는 약 30초마다 실행된다. 전환 작업은 락/클레임과 이력 앵커를 사용해 여러 번 실행되어도 동일 결과를 중복 반영하지 않도록 설계되어 있다.

### 10.3 관리자 업로드

시험 파일 구성:

- 문제 PDF
- 정답 JSON
- 선택적 해설 PDF

정답 JSON 조건:

- 정확히 30문항
- 총점 정확히 100점
- Q1–Q21: 객관식 1–5
- Q22–Q30: 단답형
- 문항 배점: 2, 3, 4점만 허용
- 선택적 해설 텍스트

여러 파일의 정렬과 매칭이 맞지 않으면 배치 전체를 롤백한다.

삭제:

- 일반 시험은 공개 전 `scheduled`/준비 상태에서만 삭제
- CUSTOM 시험은 운영 편의를 위해 더 넓은 시점에 삭제 가능

### 10.4 응시 자격

일반 사용자:

- 활성·접근 가능 계정
- 검증된 배치고사 결과
- 랭킹 프로필 존재
- 현재 사설 모의고사 무결성 제한 대상이 아님

관리자는 운영 점검을 위해 일부 자격 검사를 우회할 수 있다.

### 10.5 시작·진행·제출

- 시험 시작은 같은 사용자·시험에 대해 멱등적이다.
- 시험이 `open`이고 사용자 시작 기록이 있어야 문제 파일을 받을 수 있다.
- 개인 마감은 `min(전역 종료 시각, 개인 시작 + 100분)`.
- 임시 답안과 텔레메트리 이벤트를 저장한다.
- 텔레메트리 보관 상한은 200개.
- 마감 전에는 원채점 결과와 정답을 숨긴다.
- 제한 시간에 도달하면 브라우저 자동 제출과 별개로 서버가 시도를 만료·제출 처리할 수 있다.

### 10.6 답안 정규화와 채점

- NFKC 정규화
- 유니코드 마이너스 정규화
- 제곱근 표현 정규화
- 소문자화
- 공백 제거
- 정답 JSON의 `|`는 복수 정답 대안

심화 위치:

- 준킬러: Q20, Q21
- 킬러: Q28, Q30

표준 성능 지표는 배치/MMR과 같은 70/20/10 구조를 사용한다.

```text
actual = 0.70 × 총점 백분위
       + 0.20 × 심화 지표
       + 0.10 × 일관성
```

유효한 시험 모집단이 있으면 무효화·검토 중 시도는 백분위 모집단에서 제외한다. 유효 모집단이 전혀 없을 때만 전체를 폴백 모집단으로 사용할 수 있다. 모집단 5명 미만이면 백분위는 0.5다.

### 10.7 주간 대표 시험

한 주에 최대 3회까지 유효 시험 기록을 가질 수 있다.

- 2회 이상 응시한 사용자는 세 번째 슬롯이 닫히기 전에 직접 대표 시험을 선택할 수 있다.
- 선택하지 않으면 주간 잠금 시 서버가 자동 선택한다.
- 자동 선택 우선순위: `actual` 내림차순 → 원점수 내림차순 → 풀이 시간 오름차순.
- 같은 주의 모든 유효 시험은 안정성 지표에 사용한다.
- 공식 주간 랭킹과 MMR 기준 성과는 대표 시험을 사용한다.

주간 다회 성능 결합:

```text
1회: P
2회: 0.95 × 최고 성능 + 0.05 × 두 번째
3회: 0.90 × 최고 성능 + 0.10 × 두 번째
```

주간 순위:

1. 대표 성능 내림차순
2. 원점수 내림차순
3. 풀이 시간 오름차순
4. 생성 시각 오름차순

### 10.8 스케줄러 동작

스케줄러가 수행하는 업무:

1. 공개 시각에 시험 상태를 열고 공지
2. 종료된 진행 중 시도 만료
3. 채점 및 표준 지표 계산
4. C 시험 뒤 주간을 잠그고 대표 시험 확정
5. 공식 MMR 계산
6. 주간 결과·랭킹 게시
7. 리뷰/보관 상태 전환
8. 관리자 업로드 누락 알림 생성

업로드 누락:

- A/B/C 기준 3일 전부터 검사
- 실패·누락 알림 재시도 간격 6시간
- `sending` 상태가 10분 이상이면 정체 상태로 보고 재시도 가능

### 10.9 브라우저 시험 클라이언트

사설 모의고사 화면:

- 로비와 시작 카운트다운
- 마지막 5초 전용 연출 클래스
- 시험 마지막 30초 동안 공식·퀵 도구 숨김
- 서버와 브라우저 시계 오프셋 반영
- 답 변경 후 700ms 디바운스 저장
- 15초 주기 자동 저장
- `pagehide` 시 Beacon 저장
- 문항 포커스·답 변경·가시성·blur/focus 텔레메트리
- 마감 750ms 이내 자동 제출 시도
- 결과 발표 대기 화면에서 카운트다운 후 새로고침

브라우저가 제출을 놓쳐도 서버 마감과 스케줄러가 최종 상태를 결정한다.

## 11. 사설 모의고사 무결성·증빙·정정

### 11.1 자동 위험 신호

| 신호 | 위험 점수 |
|---|---:|
| 페이지 이탈 반복 3회 이상 | +2 |
| 마지막 1분 답 변경 8회 이상 | +2 |
| 10문항 이상 답했는데 답변 이벤트 수가 `ceil(answered/3)+1` 미만 | 신호 추가 |
| 킬러 정답 + 총 풀이 45분 미만 | +2 |
| 85점 이상 + 총 풀이 35분 미만 | +2 |
| 과거 2회 이상 데이터가 있고 최근 5회 평균보다 30점 이상 급등 | +2 |

위험 점수 4 이상이며 독립 신호가 2개 이상일 때 자동 증빙 요청 후보가 된다.

증빙 문제 선택:

- Q20, Q21, Q28, Q30 중 맞힌 문제 우선
- 조건이 안 맞으면 Q28, Q30 중심

이는 부정행위 확정이 아니라 검토 개시 신호다.

### 11.2 증빙 제출

- 파일 1–10개
- 파일당 최대 10MB
- 허용: PDF, JPEG, PNG, WEBP, HEIC
- 확장자뿐 아니라 magic bytes도 확인
- 일반 자료실 공개물이 아니라 Cloudinary 비공개 `ArchiveItem`
- 제출 완료 영수증·관리자 할 일 생성

제출 기한:

- 기본: 시험 공개일 + 3일의 한국 시간 23:59:59
- 관리자가 수동 요청한 경우: 요청 시점 + 3일

### 11.3 검토 결과와 제재

무결성 위반 확정:

- 경고 `+1`
- 앞으로 서로 다른 공식 시험 주차 3회 제한
- 해당 시도 무효화
- 랭킹·MMR에서 제외 후 재계산

혐의 해제:

- 해당 케이스가 만든 제한과 경고를 되돌림
- 시도를 유효하게 복구
- 관련 결과 재계산

경고 누적과 일반 계정 자동 정지 정책도 함께 적용될 수 있다.

### 11.4 정답 정정

관리자는 시험 종료 후 정답 정정을 등록할 수 있다.

- 문제 번호 유일
- 정정 내용 필수
- 새 정답 필수
- 객관식이면 1–5
- 기존 정답과 실제로 달라야 함

정정 시:

1. 해당 시험의 모든 시도를 재채점
2. 표준 지표와 주간 결과 재계산
3. 가장 최근 배치/시즌 리셋 기준점부터 시간순으로 모든 관련 사설 모의고사 MMR 재생
4. 사용자 알림
5. 관리자 감사 로그

### 11.5 이의제기

- 보관·게시된 일반 시험에만 가능
- CUSTOM은 제외
- 본문 최소 10자
- 관리자가 거절할 때 사유 최소 5자
- 수락은 정답 정정 흐름을 호출
- 결과 알림과 필요 시 공지 생성

## 12. 관리자 시스템

### 12.1 관리자 대시보드

표시 지표:

- 활성 학생 수
- 미처리 문의 수
- 공지 수
- 자료실 파일 수
- 최근 활동
- 통합 관리자 할 일

### 12.2 공지

- 제목에 한국 시간 날짜를 붙일 수 있음
- 카테고리
- 내부 링크
- 대시보드 노출 종료 시각
- 게시 시 모든 활성 사용자 알림을 bulk upsert
- 게시 취소 시 해당 공지성 알림 삭제
- 운영 공지는 커뮤니티 운영 게시판에도 노출

### 12.3 문의

상태:

- `pending`
- `in_review`
- `replied`
- `closed`

페이지당 20건. 답변 시:

1. 사용자에게 이메일 발송
2. 문의 상태와 답변 정보 갱신
3. 연결된 관리자 할 일 완료

이메일 실패와 상태 변경의 경계는 각 서비스 흐름에 따라 처리하며, 문의 생성 자체는 관리자 메일 전송 실패 때문에 취소되지 않는다.

### 12.4 사용자 조회

- 이름·실명·이메일 검색
- 학교·학년·상태·역할 필터
- 페이지당 20명
- 사용자 상세에서 계정, 학교, 랭킹, 학습, 평가, 커뮤니티, 제재를 결합
- 활동 페이지는 학습·문제·퀵 연습·평가·커뮤니티·모더레이션을 50건 단위로 조회
- 평가 상세는 특정 사용자의 특정 시도를 권한 검증 후 조회

### 12.5 사용자 관리 변경

보호 규칙:

- 관리자는 자기 계정을 비활성화할 수 없음
- 자기 역할을 제거하거나 자기 상태를 위험하게 변경하는 동작 제한
- 레거시 활성화 API에서도 다른 관리자 계정을 보호

역할:

- `student`
- `teacher`
- `admin`
- 변경 시 `tokenVersion +1`

상태:

- `active`
- `inactive`
- `suspended`
- `withdrawn`
- 변경 사유 기록
- 정지 기간 최대 3650일 또는 무기한
- `withdrawn`은 일반 상태 변경으로 되돌리지 않음
- 변경 시 `tokenVersion +1`

경고:

- 0–999
- 사유 필수 흐름
- 비관리자 3회 이상이면 자동 정지 가능

### 12.6 관리자 닉네임 변경 요청

1. 관리자가 사용자에게 7일 유효 보안 링크 발송
2. 기존 열린 요청 취소
3. 사용자가 링크에서 새 닉네임 가용성 검사
4. 검사 결과에 HMAC 증명 부여
5. 최종 제출에서 토큰·증명·가용성을 다시 확인
6. 저장 직전 경쟁 상태를 막기 위해 DB 중복을 다시 검사

### 12.7 직접 연락과 계정 도구

관리자는 사용자 상세에서:

- 내부 알림 발송
- 이메일 발송
- 비밀번호 재설정 링크 발송
- 계정 활성/비활성
- 역할 변경
- 계정 상태·정지 변경
- 경고 조정

모든 중요한 변경은 `AdminActionLog`에 남긴다.

### 12.8 관리자 할 일

다음 원천을 하나의 `AdminTodo`로 동기화한다.

- 문의
- 커뮤니티 신고

## 13. 커뮤니티

### 13.1 게시판

- 고등학생 게시판
- 학교 게시판
- 운영 게시판

페이지당 20개 글.

인기 글:

- 최근 72시간
- 추천 100개 이상
- 상위 5개

운영 게시판은 게시된 공지와 공지 카테고리를 기반으로 한다.

### 13.2 글과 댓글

글:

- 제목 2–120자
- 본문 2–10,000자
- 활성 계정만 작성
- 학교 게시판은 사용자 학교 정보 필수

댓글:

- 1–2,000자
- 활성 계정만 작성

익명 표시는 매 글마다 바뀌는 번호가 아니라 사용자에게 고정된 6자리 `anonymousNumber`를 쓴다. 관리자는 운영 화면에서 실제 작성자 ID를 확인할 수 있다.

글 상세 조회 시 조회 수를 증가시킨다.

### 13.3 추천

- 값 `+1` 또는 `-1`
- 사용자·글당 하나
- 같은 값을 다시 누르면 취소
- 반대 값으로 누르면 전환
- 각 변경 뒤 집계 추천/비추천 수를 갱신

### 13.4 신고

- 같은 사용자·같은 글당 1회
- 사유 최소 5자
- 자기 글 신고 금지
- 관리자 할 일 생성

### 13.5 관리자 모더레이션

- 게시글 페이지당 25개
- 최근 표시 댓글 최대 100개
- 대기 신고 조회
- 게시글 수정 시 사유 필수
- 숨김·복구·삭제
- 삭제 시 댓글·추천 연쇄 삭제
- 댓글 숨김·복구
- 신고 검토 상태 변경

경고 모더레이션:

1. 콘텐츠 숨김
2. 사용자 경고 `+1`
3. 3회 이상이면 자동 정지 및 토큰 무효화
4. 내부 알림
5. 이메일
6. 관리자 로그

동일 대상에 같은 경고를 중복 적용하지 않도록 기록을 사용한다.

### 16.9 Unranked 일반 쟁탈전 생성

- 같은 활성 Unranked의 적격 사용자만 방어 후보가 된다.
- Unranked 전 티어에서 같은 티어의 더 높은 순위 후보를 먼저 찾고, 후보가 없을 때만 정확히 바로 위 티어로 한 단계 확장한다. 챌린저는 같은 챌린저의 더 높은 순위만 대상이 된다.
- 자동 배정 방어전을 5회 시작하지 않으면 자동 방어 후보에서 제외하되 학습일수 차감은 계속한다. 참가 가능한 공격을 한 번 정상적으로 생성하면 누적을 0으로 초기화하고 자동 방어 후보 자격을 복구한다.
- 후보 조회와 경기 생성은 내부 실력 지표와 최종 종합 랭킹을 사용하지 않는다.
- 공격자는 상대 개인이나 목표 티어를 고르지 않는다.
- 서버가 같은 티어 상위 순위 후보를 우선하고 없으면 바로 위 티어 후보를 사용해 한 명을 무작위로 정한 뒤 현재 상태를 트랜잭션 안에서 다시 검증한다.
- 공격자 이용 주기의 정책 사본에 고정된 적용 일수를 경기 예치로 옮긴다.
- 양쪽 참가자 잠금으로 사용자당 미정산 공식 경기 하나만 허용한다.
- 경기, 두 참가자 잠금, 학습일수 예치 원장과 이벤트를 한 트랜잭션으로 생성한다.
- 요청 재전송은 같은 경기로 복구하며 학습일수를 중복 예치하지 않는다.
- 티어 조합당 30개 문제 묶음 슬롯 중 하나를 고르고, 경기 신청 순간 주관식 준킬러 5문항을 자동 생성·검산·봉인한다.
- 공식 모의평가 조사 카탈로그가 공개 `U1~U9`·`R1~R9`와 5슬롯 유형 골격의 근거가 된다. 실제 숫자 생성·독립 검산을 아직 구현하지 않은 골격은 실전에 사용하지 않고, ACTIVE DB 카탈로그에 연결된 승인 생성기만 신규 경기 문제를 만든다. 문제 팩에는 정책·콘텐츠·공식 참고 유형·목표 정답률·5슬롯 곡선을 저장하며, 자동 검산이나 1~999 자연수 답 선별이 실패하면 경기·문제·예치·원장을 만들지 않는다.
- 같은 트랜잭션에서 양측 `READY` 응시까지 만들어 생성 직후 응시 준비 상태가 된다.
- 경기 요청 뒤 24시간 안에 시작해야 하며, 일요일을 통과하면 시작 마감은 일요일 14:00으로 단축한다.

### 16.10 일반 쟁탈전 문제 준비·응시

- 운영자 수동 검수 대신 JS 생성기와 자동 검산을 통과한 총 5문항·100점 팩만 봉인한다. 브론즈는 기초 일반 2+일반 3에서 시작해 챌린저는 준킬러 2+킬러 3까지 단계적으로 높이며 제한 시간은 문항마다 10분이다.
- 봉인 팩 전체 콘텐츠 해시가 일치해야 실제 경기에 배정한다.
- 양측에는 난이도와 내용이 완전히 같은 문제를 제공한다. Unranked는 방어자 티어의 `U1~U9`, Ranked는 `R1~R9`를 사용하고 같은 숫자의 R등급이 U등급보다 어렵다. 각 공개 난이도에는 실제 경기 선택에 쓰는 최소 30개 유형 ID가 있다.
- 그래프·표·도식은 문제 본문이 실제 제시 자료라고 명시하고 생성 수치에 대응하는 식·라벨·좌표 데이터가 있을 때만 흰색 문제지에 표시한다. 풀이과정에서만 사용된 보조 그래프는 표시하지 않는다.
- 각 참가자는 서로 다른 시각에 시작할 수 있으며 자신의 서버 시작 시각부터 같은 제한 시간이 흐른다.
- 한 화면에는 현재 문제 하나만 표시하며 다음 문제로 이동하면 이전 문제와 답을 다시 보거나 수정할 수 없다.
- 문항별 풀이시간과 전체 풀이시간, 답안 변경 snapshot, heartbeat·focus 이벤트를 서버 수신 시각과 함께 보존한다.
- 5번 문제 완료 또는 제한 시간 종료 뒤 문제를 닫고 60초 풀이 증거 제출 단계로 전환한다.
- 답은 1~999 자연수만 허용한다. 빈 답은 미응답이며 분수·소수·동치식은 Arena 1대1 입력 형식에 포함하지 않는다.
- 모든 풀이 증거를 운영자가 열람할 수 있고 이상 징후는 관리자 알림으로 만든다.
- 상대가 배정되기 전에는 개인 후보를 공개하지 않는다. 매치가 성립한 뒤에는 서비스 닉네임만 표시하고 실명·학교·지역·연락처는 보내지 않는다.
- Unranked 일반 쟁탈전과 복수전은 서버 채점·무결성 확인 뒤 승패·GP·티어·티어 내 순위와 페이백 점수를 자동 정산한다. Ranked 경기 정산은 학습일수 장부로 별도로 처리한다.

### 20.6 고2·고3 수험관

기존 Matths 상점 위치(`/store`)는 고2·고3 수험관으로 사용한다. 사용자 화면은 자체제작 N제, 데일리 하프, 실전 모의고사, 수능 파이널, 개념 학습, 오답 유형 리포트의 고정 탭 6개로 구성한다.

- 자체제작 N제·수능 파이널·개념 학습은 PDF를 내려받는 문제집이 아니라 플랫폼 문항을 직접 풀고 임시 저장·이어 풀기·최종 제출하는 콘텐츠다.
- 데일리 하프는 연도→월→주차→회차로 분류하며 1~15번 답안 마킹, 임시 저장, 최종 제출, 결과·해설 확인을 제공한다.
- 실전 모의고사는 시기·시리즈, 제한 시간, 문항 수, 문제지, 답안 마킹, 제출 결과와 해설을 함께 관리한다.
- 오답 유형 리포트는 운영자가 제작한 오답 원인·잘못된 접근·올바른 풀이·대표 문제와 연결 자료를 공개한다.
- 운영자는 주간 공식 모의고사 답지와 같은 `matths-answer-key-v1` JSON을 업로드할 수 있다. 30문항 모의고사는 주간 공식 모의고사와 같은 1~21번 객관식·22~30번 주관식·100점 검증을 그대로 적용하고, 데일리 하프처럼 문항 수가 다른 콘텐츠도 같은 `questions` 또는 `answers`·`points`·`questionModes`·`explanations` 필드 구조를 사용한다.
- `StudyHallContent`는 콘텐츠·문항·R2 자산·공개 상태·노출 순서를 저장하고, `StudyHallProgress`는 사용자별 답안·진행률·최종 제출·다운로드 이력을 저장한다.
- 문제지·해설·표지·연결 파일은 Cloudflare R2 비공개 객체로 저장한다. 공개 상태와 공개 시각을 서버에서 확인하고, 해설 PDF는 최종 제출 뒤에만 짧은 만료 시간의 서명 URL로 제공한다.
- 최종 제출 시 주간 공식 모의고사와 같은 답안 정규화·복수 정답 비교를 적용하고 문항별 배점으로 점수·정답 수·정답률을 계산한다. 제출 뒤 정오답·정답·배점·등록 해설을 표시하며 업로드 JSON 파일 자체는 변환 뒤 삭제하고 정답 데이터만 DB에 보존한다.
- 최종 제출은 한 번만 허용하고, 공개 콘텐츠의 문항 수와 정답 데이터 수가 일치하지 않으면 공개를 차단한다. 데일리 하프는 정확히 15문항이어야 한다.
- 관리자는 콘텐츠 종류, 시리즈, 학년·과목, 제목·설명, 문항·정답·해설, 난이도, 공개 시각·순서·상태와 R2 파일을 개발자 도움 없이 등록·수정·비공개 보관할 수 있다.

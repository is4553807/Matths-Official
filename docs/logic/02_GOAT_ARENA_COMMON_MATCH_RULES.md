# GOAT Arena 공통 1대1 경기 규칙

> 상태: Division 공통 기반  
> 우선순위: 각 Division 최종 규칙보다 낮음  
> Sub 전용 수치·정산: [`03_SUB_DIVISION_RANKING_SYSTEM_PAYBACK.md`](./03_SUB_DIVISION_RANKING_SYSTEM_PAYBACK.md)
> Main 전용 규칙: [`04_MAIN_DIVISION_RANKING_SYSTEM.md`](./04_MAIN_DIVISION_RANKING_SYSTEM.md)
> Main 전용 상점: [`12_SHOP.md`](./12_SHOP.md)

이 문서는 Sub와 Main이 함께 사용하는 경기 진행, 문제 공정성, 서버 판정, 기록 원칙을 정의한다. 공격 대상, 예치·복수전 경제와 페이백 수치는 Division 문서에서 정한다. 복수전의 문제·채점·증거·승패 판정은 공통이지만 예치와 No-show 정산은 Sub와 Main이 서로 다르다. 모든 1대1 경기의 MMR 분리와 Arena 상태 교환 원칙은 이 문서의 공통 불변식으로 적용한다.

## 1. Division 분리 원칙

- Sub와 Main은 참가자 풀, 랭킹, 경제 자산과 정책 버전을 분리한다.
- 서로 다른 Division 사용자는 공식 랭킹 경기에서 만나지 않는다.
- Sub 자산이나 결과를 Main 규칙에 임의로 전환하지 않는다.
- Main 진입 여부는 Sub 평가 결과일 수 있지만, 진입 후 Main 경기 규칙을 뜻하지 않는다.
- 클라이언트가 보낸 Division, 상대, 예치 일수, 랭크를 권위 값으로 신뢰하지 않는다.

## 1.1 모든 1대1 경기의 MMR 분리 불변식

일반 1대1과 복수전은 MMR과 완전히 분리한다.

```text
MMR
= 배치고사 및 매주 일요일 공식 모의고사에서만 변경

Arena 상태
= Arena 랭크 + Arena 랭크 내 순위 + Arena GP
```

1대1 서비스는 다음 목적으로 MMR을 읽거나 사용하지 않는다.

- 상대 후보 선정
- 공격 자격 또는 방어 자격
- 문제 난이도 배정
- 승패 판정
- 타이브레이커
- Arena 상태 교환 여부
- 학습일수 정산
- 일일 공격·방어 상한

### 도전자가 승리한 경우

두 사용자의 Arena 상태 3종을 한 묶음으로 통째로 교환한다.

```text
swap(challenger.arenaRank, defender.arenaRank)
swap(challenger.arenaPosition, defender.arenaPosition)
swap(challenger.arenaGp, defender.arenaGp)
```

도전자는 방어자가 경기 전에 보유한 Arena 랭크·순위·GP를 모두 받고,
방어자는 도전자가 경기 전에 보유한 Arena 랭크·순위·GP를 모두 받는다.

### 방어자가 승리한 경우

```text
Arena 랭크 교환 없음
Arena 순위 교환 없음
Arena GP 교환 없음
MMR 변경 없음
```

학습일수 정산만 Division 정책에 따라 수행한다.

### MMR 변경 경로

배치고사와 Matths 주간 공식 모의고사 정산만 MMR을 변경한다. Matths 주간 공식 모의고사 이용권 사용자는 배치고사 없이도 주간 공식 모의고사로 MMR 시계열을 먼저 만들 수 있지만, 이 값만으로 GOAT Arena에 입장하거나 Arena 상태를 받을 수 없다.

일요일 공식 모의고사로 갱신된 MMR은 Final Ranking의 핵심 입력으로 사용한다.
Final Rating 계산은 Sub·Main Division 성과를 읽기만 하며,
Arena GP 또는 Arena 랭크·순위를 변경하지 않는다.
해당 작업은 1대1 Match 정산과 분리된 별도 정책·이벤트·트랜잭션으로 처리한다.

## 1.2 Final Ranking과 1대1의 경계

Final Ranking은 1대1 경기의 입력이나 정산 결과가 아니다.

- Final Rating으로 상대를 배정하지 않는다.
- Final Rank로 문제 난이도를 바꾸지 않는다.
- 1대1 결과 직후 Final Rating에 보너스를 누적하지 않는다.
- 정산된 Arena 상태 변화가 있으면 Final Rating을 공식으로 실시간 재계산한다.
- Division 기본점수와 성장·위치점수는 매번 덮어쓰며 중복 누적하지 않는다.
- Final Ranking은 Skill MMR과 Division 성과를 권위 입력으로 다시 계산하되, 그 계산 결과로 Skill MMR이나 Arena 랭크·순위·GP를 변경하지 않는다.

자세한 공식은
[`08_FINAL_RANKING_SYSTEM.md`](./08_FINAL_RANKING_SYSTEM.md)를 따른다.

## 1.3 구독·학습권 기반 경기 자격

공식 1대1 참가자는 다음을 모두 만족해야 한다.

`Matths 주간 공식 모의고사 이용권`은 이 조건의 유료 학습권 패키지로 취급하지 않는다. 해당 상품은 Matths 주간 공식 모의고사만 허용하며 배치고사와 GOAT Arena 일반 쟁탈전·복수전을 모두 차단한다.

```text
currentSeasonPlacementCompleted = true
AND accountStatus = ACTIVE
AND availableLearningDays > 0
AND accessState = PAID_ACTIVE
AND sundayDivisionLock = false
```

Sub는 사용 가능한 학습일수가 0이 되면 공격·방어·복수전과 신규 매칭을 즉시 중단한다. Main은 새 경기 양측이 `availableLearningDays > stakeDays`를 만족해야 하며, 사용 가능 잔액이 0이고 미성립 초대 예약이 있으면 Main 정책에 따라 예약을 먼저 취소·반환한다.

```text
availableLearningDays = 0
→ ACCESS_EXPIRED_LOCKED
→ defensePoolEligible = false
```

Main 최종 만료·Sub 강등은 다음 조건을 모두 만족할 때만 처리한다.

```text
availableLearningDays = 0
AND reservedLearningDays = 0
AND lockedLearningDays = 0
AND noPendingSettlement
```

만료 사용자는 무료 방어자로 남지 않는다.

진행 중 경기의 예치 학습권이 남아 있으면 정산을 우선하고,
정산 완료 뒤 만료 상태로 전환한다.

## 1.4 재구독과 Arena 재진입

Main 사용자의 총 학습일수가 끝나면 Main에서 Sub로 강등되고 GOAT Arena 이용이 잠긴다.
재결제하면 강등된 Sub Division에서 새 결제주기의 페이백 경쟁을 시작한다.

```text
72시간 이내 재구독
→ Main-to-Sub Rank Convert
→ 시험 없음

72시간 초과 재구독
→ 재구독 랭크 결정전
→ Sub 재진입 랭크 확정
```

늦은 재구독자는 시험 최고점을 받아도
정상 72시간 내 갱신 시 받을 변환 랭크보다 높은 위치에 배치할 수 없다.

`재구독 랭크 결정전`은 Skill MMR 배치고사가 아니라
Sub Arena 재진입 Seed를 결정하는 시험이다.

## 2. 공통 경기 생명주기

```text
자격 확인
→ 상대 후보 결정
→ 정책 버전·경기 조건 고정
→ 문제 자동 생성·검산·봉인
→ 필요한 학습일수 예치와 양측 READY 생성
→ 양측 응시·답안 저장
→ 서버 채점
→ 무결성 검사
→ 결과 확정 또는 보류
→ Arena 상태·자산·통계를 원자적으로 정산
→ 알림·기록 이벤트 발행
```

권장 상태:

```text
REQUESTED
→ MATCHED
→ READY
→ IN_PROGRESS
→ SUBMITTED
→ RESOLVED | HELD | INVALID
→ SETTLED | CANCELLED | INSURED_CANCELLED
```

- 한 사용자는 같은 시점에 정산되지 않은 공식 경기를 하나만 가진다.
- `HELD` 상태에서는 Arena 상태와 학습일수를 확정하지 않는다.
- 이미 `SETTLED`된 경기는 같은 요청이 다시 와도 재정산하지 않는다.
- 경기 시작 시점의 `PolicyVersion`과 문제·채점 버전을 끝까지 유지한다.

## 2.1 일요일 공통 신규 경기 마감과 공통 잠금

Sub Division과 Main Division은 매주 일요일 14:30부터 신규 경기 신청·수락·준비·시작을 차단한다.
Main Division의 일반 상향 공격 매칭, 하위 티어 초대 수락·매치 성립과 복수전 신청·수락·시작도 같은 14:30 마감을 적용한다.
진행 중 경기는 15:00 전에 답안·풀이 증거 제출과 정산을 끝내야 하며,
15:00부터 월요일 00:00까지 Sub와 Main에 진행 중인 공식 1대1 경기가 없어야 한다.

잠금 대상:

- 일반 공격·방어 매칭
- 복수전 신청·수락·시작
- Arena 상태를 변경할 수 있는 공식 정산

```text
subNewMatchRequestCutoff = Sunday 14:30
mainNewMatchRequestCutoff = Sunday 14:30
arenaWriteLock = Sunday 15:00
```

15:00까지 정산되지 않은 예외 경기는 `HELD` 처리하며
일요일 Division 스냅샷을 변경하지 않는다.

잠금 중 공개 Final Ranking은 15:00 상태로 고정한다. 정상 이용자의 공식 모의고사 MMR과 Weekly Mock Bonus, 새 Final Rank는 staging에서 계산한 뒤 월요일 00:00에 Arena 잠금 해제와 함께 일괄 공개한다. 학습권 만료 사용자는 시험과 staging 대상에서 제외한다.

## 2.2 Sub Division 일반 쟁탈전 생성

현재 구현된 최초 생성 범위는 다음과 같다.

```text
신청자 자격 확인
→ 같은 활성 Sub Division의 적격 방어자 조회
→ 사용자가 목표 티어만 선택
→ 서버가 해당 티어의 적격 방어자 한 명을 무작위 선정·재검증
→ 공격자 적용 일수 예치
→ 양쪽 참가자 공식 경기 잠금
→ 자동 봉인 문제·READY 경기·양쪽 응시·원장·이벤트 생성
```

- 사용자는 상대 개인을 고를 수 없고 목표 티어만 고른다.
- 상대 후보는 같은 활성 Sub Division에서 도전자의 바로 위 티어만 찾고, 서버가 한 명을 무작위 선정해 자동 참가시킨다.
- 브론즈는 브론즈·실버, 챌린저는 챌린저에게 도전할 수 있는 경계 예외를 둔다.
- 상대가 배정되기 전에는 개인 후보 목록과 닉네임을 공개하지 않는다. 매치가 성립한 뒤 경기 화면에는 서비스 닉네임을 표시하되 학교·지역·연락처는 공개하지 않는다. 유저가 GOAT Arena에서 실명 사용하기 설정을 했다면 실명을 공개한다. 하지만 학교·지역·연락처는 공개하지 않는다.
- 실버 이상 챌린저 미만의 사용자는 같은 티어 또는 두 티어 이상 차이 나는 상대에게 일반 쟁탈전을 신청할 수 없다.
- 후보 정렬 순서는 서버 내부 선별에만 사용하고 개인 후보 목록은 사용자 화면에 표시하지 않는다.
- 내부 실력 지표와 최종 종합 랭킹은 후보 선정에 사용하지 않는다.
- 클라이언트가 보낸 목표 티어만 입력으로 받고, 서버가 선정한 상대의 순위 문서는 현재 시즌·사용자·접근 상태·이용 주기와 다시 대조한다.
- 적격 상대가 없으면 경기·참가자 잠금·학습일수 예치 원장을 만들지 않는다.
- Sub Division 일반 쟁탈전은 전 이용 주기에 1일 고정값을 적용한다.
- 일반 쟁탈전 생성 시 공격자의 정기권 학습 가능 일수를 경기 예치로 옮기며, Sub 방어자는 생성 단계에서 일수를 예치하지 않는다.
- 공격자와 방어자 모두 참가자 잠금을 얻어 한 시점에 미정산 공식 경기 하나만 가질 수 있다.
- 요청 식별자 재전송은 같은 경기로 응답하고 일수·원장·이벤트를 중복 생성하지 않는다.
- 경기 요청 뒤 양측은 24시간 안에 시작해야 한다. 단, 일요일을 통과하는 요청의 시작 마감은 24시간보다 이른 일요일 14:30이다.
- 일요일 14:30부터 월요일 00:00까지 신규 경기 생성을 차단한다.
- 신청 순간 두 사용자의 티어 조합을 고정하고 방어자 티어 기준 T1~T9 문제 5문항을 자동 생성·자동 검산한다. 실제 문항 생성 원본은 배치고사 심화 준킬러를 Arena 전용 JS 파일에 독립 복사한 임시 버전이며, 관리자가 적용한 `ArenaProblemDataVersion`에서 해당 T 난이도에 허용된 서로 다른 5개 유형을 배정한다. 생성된 팩은 문제 데이터 버전 ID·콘텐츠 버전·문항·정답·해시를 함께 봉인하므로 이후 관리자 변경이 진행 중 경기에 소급되지 않는다. 최종 티어별 생성기가 연결되기 전에는 팩을 `PENDING_FINAL_GENERATORS`로 표시하고 2·2·1 단원 배분까지 준수한다고 기록하지 않는다. 유형 누락이나 자동 검산 실패 시에는 학습일수를 예치하기 전에 신청을 거절한다.

## 2.3 문제 팩 배정과 양측 응시

현재 구현 범위는 다음과 같다.

```text
경기 신청 트랜잭션
→ 티어 조합별 문제 즉시 생성·자동 검산·봉인
→ 같은 문제·배점·제한 시간·채점 버전 고정
→ 양쪽 READY 응시 문서 생성
→ 참가자가 각자 시작하면 IN_PROGRESS
→ 답안 변경·heartbeat·focus 이벤트 서버 저장
→ 수동 제출 또는 제한 시간 자동 제출
→ 양쪽 제출 완료 시 경기 SUBMITTED
```

- 실제 경기에는 자동 검산을 통과하고 콘텐츠 해시가 고정된 `SEALED` 문제 팩만 배정한다.
- 문제 팩은 주관식 준킬러 5문항·총점 100점·제한시간 10분이며 두 사용자에게 같은 문제를 제공한다.
- 티어 조합마다 30개 문제 묶음 슬롯을 두고, 각 묶음은 서로 다른 유형 5개로 구성한다. 유형 생성기는 경기마다 숫자를 바꿔 새 문항을 만든다.
- 문제 난이도는 두 사용자에게 완전히 같고 Sub·Main 모두 방어자 티어를 기준으로 T1~T9 중 하나를 고른다. Main에서 티어 차이가 2~3단계여도 방어자 티어가 같으면 같은 T등급을 사용한다.
- 운영자 수동 문제 검수는 요구하지 않는다. JS 생성기와 검산기가 해답 일치·유일답·계산기 불필요·풀이 가능 여부를 모두 통과시켜야 한다.
- 봉인 시 문항·정답·해설·배점·난이도·제한 시간·채점 버전 전체의 해시를 저장하며 배정할 때 서버가 다시 검증한다.
- 두 참가자는 동시에 접속할 필요가 없다. 각 참가자가 시작한 서버 시각부터 같은 길이의 개인 제한 시간이 흐르며 화면을 닫아도 멈추지 않는다.
- 정답과 해설은 참가자 응답에 포함하지 않는다.
- 한 화면에는 현재 문항 하나만 표시한다. `다음 문제`를 누르면 답을 확정하고 이전 문항의 내용·답안을 다시 열람하거나 수정할 수 없다.
- 5번 문항에서 다음 버튼을 누르거나 10분이 끝나면 문제 화면을 즉시 닫고 1분 풀이 증거 제출 화면으로 전환한다.
- 풀이 증거는 양측 모두 사진 1~5장을 서버에 60초 안에 업로드 완료해야 하며 상대에게 공개하지 않는다.
- 운영자는 모든 경기 증거를 관리자 화면에서 열람할 수 있고, 동일 파일·비정상적으로 빠른 풀이·반복 화면 이탈 등 이상 징후는 자동 알림으로 받는다.
- heartbeat와 focus 이벤트의 클라이언트 시각은 참고값으로만 저장하고 서버 수신 시각을 함께 남긴다. 유효 풀이시간 계산은 후속 판정 단계에서 수행한다.
- 시작·답안 저장·활동 기록·제출은 요청 식별자로 멱등 처리한다.
- 제한 시간이 끝난 미제출 응시는 서버 작업이 마지막 저장 답안으로 자동 제출한다.
- Sub Division과 Main Division 모두 일요일 14:30 이후 새 경기 준비·시작을 허용하지 않는다. 두 Division 모두 15:00부터 답안 변경·활동 기록·제출과 자동 제출을 진행하지 않으며 예외 미정산 경기는 `HELD`로 보낸다.
- 한 명만 제출한 동안 경기는 `IN_PROGRESS`를 유지하고, 양쪽이 모두 제출하면 `SUBMITTED`가 된다.
- 증거 제출 시 3자리 이하 자연수 답을 서버에서 채점해 개인 점수·정답 수를 저장한다. 양측 증거와 무결성 확인이 끝나면 해당 Division의 확정 정산표에 따라 승패, GP·티어·티어 내 순위와 정기권 학습 가능 일수를 한 트랜잭션으로 반영한다.

## 3. 문제 구성과 공정성

이 절은 Sub·Main의 일반 쟁탈전과 복수전에 공통으로 적용한다. 정책 코드는 `GOAT_ARENA_SEMI_KILLER_V2`이며 문제 팩에는 정책 버전과 콘텐츠 원본 버전을 각각 저장한다.

### 3.1 방어자 앵커 T1~T9

난이도는 언제나 방어자 티어로 결정한다. Final Rank, MMR, 도전자 실력이나 예치 일수로 문제 난이도를 바꾸지 않는다.

| 기본 매치업 | 방어자 앵커 | 등급 |
|---|---:|---:|
| 브론즈 → 브론즈 | 브론즈 | T1 |
| 브론즈 → 실버 | 실버 | T2 |
| 실버 → 골드 | 골드 | T3 |
| 골드 → 플래티넘 | 플래티넘 | T4 |
| 플래티넘 → 에메랄드 | 에메랄드 | T5 |
| 에메랄드 → 다이아몬드 | 다이아몬드 | T6 |
| 다이아몬드 → 마스터 | 마스터 | T7 |
| 마스터 → 그랜드마스터 | 그랜드마스터 | T8 |
| 그랜드마스터 → 챌린저 | 챌린저 | T9 |
| 챌린저 → 챌린저 | 챌린저 | T9 |

Main의 2~3단계 차이 경기에도 같은 원칙을 적용한다. 예를 들어 실버가 에메랄드 방어자와 경기하면 도전자 티어와 무관하게 에메랄드 앵커 T5를 사용한다.

| 등급 | 앵커 | 방어자 목표 | 도전자 예상 |
|---|---|---:|---:|
| T1 | 브론즈 | 60~68% | 동티어 60~68% |
| T2 | 실버 | 58~65% | 42~50% |
| T3 | 골드 | 56~63% | 40~48% |
| T4 | 플래티넘 | 54~61% | 38~46% |
| T5 | 에메랄드 | 52~59% | 36~44% |
| T6 | 다이아몬드 | 50~57% | 34~42% |

- 방어자 목표는 대체로 45~60%에 둔다.
- 다른 티어끼리 경기할 때 도전자의 예상 정답률은 방어자보다 12~18%p 낮게 설계한다.
- T1에서 T9로 갈수록 절대 난이도가 올라가며, 티어별 목표 정답률이 비슷한 것은 사용자 실력도 함께 올라가기 때문이다.

### 3.3 준킬러 정의와 고정 경기 규격

```text
문항 수 = 준킬러 5문항
배점 = 문항당 20점, 총 100점
제한 시간 = 10분, 문항당 목표 2분
문제 = 양측 완전 동일
답 = 1~999 자연수 주관식
```

준킬러는 개념 2개 이상을 결합하고 조건을 최소 한 단계 변형해야 식이 나오는 문항이다. 개념 하나를 직접 대입해 끝나는 워밍업 문항은 T1에도 넣지 않는다. 답은 현재 문항에서 다음 버튼을 누르기 전까지만 변경할 수 있고, 다음 문항으로 이동한 뒤에는 직전 문제의 답과 문제 내용을 다시 볼 수 없다.

| 등급 | 개념 결합 | 조건 수 | 해석 깊이 | 경우분류 | 그래프 |
|---|---:|---:|---:|---:|---|
| T1 | 2 | 1 | 직접 | 0 | 완전 제공 |
| T2 | 2 | 1 | 직접 | 1 | 완전 제공 |
| T3 | 2 | 2 | 1단계 | 1 | 완전 제공 |
| T4 | 2 | 2 | 1단계 | 2 | 완전 제공 |
| T5 | 2~3 | 2 | 1단계 | 2 | 일부 제공 |
| T6 | 3 | 2 | 2단계 | 3 | 일부 제공 |
| T7 | 3 | 2~3 | 2단계 | 3 | 일부 제공 |
| T8 | 3 | 3 | 2단계 | 3 | 최소 제공 |
| T9 | 3 | 3 | 2단계 | 4 | 직접 구성 |

계산량은 T1~T9 모두 낮게 고정한다. 상위 등급의 난이도는 계산량이 아니라 조건 하나의 해석 깊이, 경우분류와 개념 결합에서 만든다.

### 3.5 5문항 팩 구성

- 기본 곡선: `하단 / 중심 / 중심 / 중심~상단 / 상단`
- 챌린저→챌린저: `중심 / 중심 / 상단 / 상단 / 상단`
- 단원 배분: 대수 2, 미적분Ⅰ 2, 확률과 통계 1
- 같은 단원 최대 2문항
- 그래프 문항 최소 1개, T5 이상 최대 2개
- 직전 3경기에 사용한 유형 ID 재사용 금지
- 5문항 모두 준킬러이고 계산량은 낮게 유지

현재 임시 생성기는 자연수 답과 서로 다른 5유형을 보장하지만, 최종 유형 생성기가 들어오기 전까지 단원 2·2·1, 그래프 수, 직전 3경기 유형 제외를 완전 준수한다고 표시하지 않는다. 최종 생성기를 활성화할 때 `designCompliance=ACTIVE`로 바꾸고 팩 검증기가 이 조건을 강제한다.

### 3.6 티어별 허용 유형 카탈로그

아래 카탈로그의 유형 ID는 `arenaOneOnOneDifficultyPolicy.js`와 동일해야 한다. 실제 숫자·조건 생성 함수는 이후 `arenaOneOnOneProblemTypes.js`에서 같은 ID에 연결한다.

#### T1 브론즈

- 대수: 등차수열 일반항+부분합, 등비수열 항+합, 지수법칙+로그 정의
- 미적분Ⅰ: 좌·우극한 그래프 판독, 접선 기울기→방정식, 한 구간 정적분 넓이
- 확률과 통계: 뽑고 나열하는 순열·조합 2단계, 이항분포 평균·분산
- 금지: 본격 경우분류, 미정계수 역추적, 그래프 미제공

#### T2 실버

- 대수: 귀납적 정의 순차 계산, Σk+Σk², 특수각+부채꼴
- 미적분Ⅰ: 사차함수 극솟값, 속도→위치 변화량, 정적분 값→계수 1개
- 확률과 통계: 여사건 2단계, 확률변수 일차변환 평균·분산

#### T3 골드

- 대수: 부분분수·망원합, 삼각함수 주기·이동→계수, 지수·로그 교점·대칭, 등차·등비중항
- 미적분Ⅰ: 극값→미정계수 2개, 연속 조건 미정계수, 넓이→계수
- 확률과 통계: 정규분포 표준화, 조건부확률 1단계

#### T4 플래티넘

- 대수: 등차수열 부분합 최댓값, 삼각함수·직선 교점의 합, 사인·코사인법칙+도형, 로그 부등식 정수해
- 미적분Ⅰ: 곡선·직선 넓이→계수, 삼차함수 개형+극값, 두 곡선 사이 넓이
- 확률과 통계: 같은 것이 있는 순열+여사건, 이항분포 분산→n→평균

#### T5 에메랄드

- 대수: 삼각함수 최대·최소+치환, 수열의 합→일반항, 지수·로그 치환 방정식
- 미적분Ⅰ: 부호가 바뀌는 구간 분할 넓이, 삼차함수 실근 수→정수 계수, 속도 그래프 이동거리·변위
- 확률과 통계: 중복조합+변수 치환, 조건부확률 2단계, 표본평균 분포+구간

권장 슬롯 예시는 `대수 하단 / 미적분Ⅰ 중심 / 확통 중심 / 대수 중심~상단 / 미적분Ⅰ 상단`이다.

#### T6 다이아몬드

- 대수: 삼각방정식 해 개수, 귀납 수열+곱=0 경우분해, 로그 진수·밑 조건
- 미적분Ⅰ: 구간별 함수 연속·미분가능, 한 점을 지나는 접선→접점, 같은 넓이→계수
- 확률과 통계: 주머니 이동 2단계, 조건을 만족하는 함수 개수

#### T7 마스터

- 대수: 조건 나열형 수열, 삼각함수+도형 최댓값, 등비수열+부등식
- 미적분Ⅰ: 조건 나열형 삼차함수, 속도·거리 역문제, 접선과 곡선의 넓이
- 확률과 통계: 단조·전사 일부 조건 함수 개수, 확률변수 모멘트 결합

#### T8 그랜드마스터

- 대수: 귀납 수열+최대·최소, 외접원·삼각함수·넓이, 로그 그래프+도형 넓이
- 미적분Ⅰ: 적분 정의 함수의 미분가능성, 삼차함수 접선 3조건, 극값·현 넓이
- 확률과 통계: 3회 이상 반복 조건부확률, 중복조합+제한 조건 2개

#### T9 챌린저

- 대수: 수열+절댓값·최대최소 복합, 삼각함수 합성+해 개수 역조건
- 미적분Ⅰ: 절댓값·구간분할 미분가능, 접선·적분·극값, 적분함수 접선 역문제, 속도 부호 전환 거리 역문제
- 확률과 통계: 부분집합 포함배제, 전사함수·제한 분포
- 계산량은 올리지 않고 상호 제약 조건과 최대 4회 경우분류로 난이도를 만든다.

### 3.7 문항·팩 검수

문항 하나마다 다음을 모두 확인한다.

- 개념 2개 이상 결합 + 조건 한 단계 이상 변형
- 유일한 답, 1~999 자연수, 대수·미적분Ⅰ·확률과 통계 범위
- 누락·충돌 조건 없음, 독립 계산한 풀이와 답 일치
- 표시 티어와 풀이 부담 일치, 2분 안에 풀이 가능
- 계산량이 아니라 논리에서 난이도가 발생
- 기출·자체 문항의 과도한 복제 금지

팩 단위로는 준킬러 5문항, 2·2·1 단원, 그래프 1~2문항, 티어 내 난이도 곡선, 직전 3경기 유형 ID 제외를 검증한다. 문항 생성은 기존 유형은행 유형 2~3개를 재료로 사용하고 별도 조건 추론층을 결합하며, 유형은행의 개념 연습용 `difficulty 1~3`을 Arena T1~T9에 직접 대응시키지 않는다.

### 3.8 실측 보정과 버전

문항 유형별 최소 30경기가 쌓인 뒤에만 보정한다. 모든 결과에 `PolicyVersion`을 저장해 당시 정책을 재현한다.

| 신호 | 조치 |
|---|---|
| 방어자 정답률이 목표 상단보다 8%p 초과 | 경우분류 +1 또는 그래프 제공 축소 |
| 방어자 정답률이 목표 하단보다 8%p 미만 | 조건 -1 또는 그래프 제공 확대 |
| 방어자·도전자 정답률 차가 8%p 미만 | 상단 슬롯 한 등급 상향 |
| 정답률 차가 25%p 초과 | 하단 슬롯 한 등급 하향 |
| 5문항 만점 경기 15% 초과 | 5번 슬롯 상향 |
| 무득점 경기 10% 초과 | 1번 슬롯 하향 |
| 완전 동점 20% 초과 | `하단/중심/중심/상단/상단` 곡선 검토 |

업로드 설계표의 `서든데스 발생률`은 현행 서비스에 별도 서든데스 경기가 없으므로 `완전 동점 발생률`로 측정한다. 현행 완전 동점은 방어자 승리 규칙을 유지한다.

다음 오류를 금지한다: 도전자 티어 앵커, 상위 티어의 계산량 증가, 유형은행 난이도 직접 매핑, 5문항 동일 난이도, 워밍업 문항, 한 단원 3문항, 챌린저 목표 정답률 15% 설계.

## 3.9 복수전 권리와 진행

- 가장 최근에 끝난 원경기의 패자에게 결과 화면에서 한 번만 복수전 선택권을 준다.
- `복수하기`를 누르면 권리를 즉시 사용하고 상대는 별도 수락 없이 자동 참가한다.
- `경기 종료`를 누르거나 결과 화면에서 복수전 권리를 포기하면 같은 원경기로 다시 신청할 수 없다.
- 복수전은 원경기·권리·신청자·상대·Division 정책 버전을 고정해 한 번만 생성한다.
- 신청 후 24시간 안에 양측이 문제 풀이를 완료해야 하며 일요일 14:30을 넘길 수 없다.
- 문제·채점·증거 제출·Arena 상태 교환 기준은 일반 쟁탈전과 같고, 예치·수수료·No-show 반환·소각량만 Division 문서를 따른다.
- 복수전 신청자가 미완료하면 방어자 승리로 처리하고 Arena 상태는 교환하지 않으며, 신청자가 예치한 학습일수는 해당 Division 정산 정책에 따라 처리한다.

## 4. 승패 판정

현재 채점 단계는 각 참가자에게 다음 값을 계산해 저장한다.

```text
score
correctCount
correctAnswerSolveTimeMs
totalSolveTimeMs
```

- 점수와 정답 성과가 시간보다 우선한다.
- 브라우저가 보낸 시간 숫자를 그대로 사용하지 않는다.
- 서버 시각, heartbeat, focus 이벤트와 네트워크 유예 정책으로 유효 풀이시간을 산정한다.
- 문제 오류나 서버 장애로 공정한 판정이 불가능하면 방어자 승리로 강제하지 않고 `HELD` 또는 `INVALID`로 보낸다.
- 승패 우선순위는 `점수 높은 순 → 정답 수 많은 순 → 정답 문항 풀이시간 짧은 순 → 전체 풀이시간 짧은 순`이다.
- 네 값이 모두 같으면 방어자 승리로 처리한다. Main Division도 같은 순서를 사용한다.

Sudden Death는 현재 정책에 포함하지 않는다.

## 5. 익명성과 개인정보

- 자동 상대 선정 전에는 개인 후보를 공개하지 않는다.
- 실명, 학교, 지역, 연락처, 결제 정보와 공모 탐지 신호는 공개하지 않는다. 단 유저가 GOAT Arena에서 실명 쓰기를 설정에서 적용한다면 실명은 공개한다. 하지만 학교, 지역, 연락처, 결제 정보와 공모 탐지 신호는 공개하지 않는다.
- 매치 성립 뒤에는 상대의 서비스 닉네임과 경기상 필요한 Arena 정보만 표시한다. 정산 뒤 내 전적에서는 공개 프로필·경기 당시 Division·티어·GP·순위를 함께 확인할 수 있다. 실명·학교·지역·연락처·결제 정보는 공개하지 않는다. 단 유저가 GOAT Arena에서 실명 쓰기를 설정에서 적용한다면 실명은 공개한다.
- 탈퇴 사용자의 과거 경기·랭킹 이력은 운영상 필요한 기록을 유지하되 공개 화면에서는 익명화한다.

Sub Division과 Main Division은 위 공개 범위를 공통 최소 기준으로 적용한다. Division별 추가 공개 항목은 명시적으로 확정된 정책 버전에 있을 때만 제공한다.

## 6. 서버 권위와 멱등성

서버가 직접 계산하거나 재검증해야 하는 값:

- 계정·결제주기·Division 참가 자격
- 상대 후보와 재매칭 제한
- 현재 Arena 랭크·Arena 순위·Arena GP와 당일 사용 횟수
- 예치할 학습일수와 사용 자산
- 문제 팩과 채점 정책
- 시작·종료 시각과 유효 풀이시간
- 승패, Arena 상태 3종의 교환 여부, 이전·반환·소각량
- streak, 최소 공격과 페이백 자격

다음 동작은 고유 멱등 키를 사용한다.

```text
challenge request

submission

```

## 7. 정산 공통 불변식

- 모든 학습일수 변화는 불변 원장 거래로 설명할 수 있어야 한다.
- 학습일수 예치, 결과, Arena 상태 교환, 카운터와 원장 거래는 한 정산 트랜잭션에서 확정한다.
- 확정 원장 기록은 수정·삭제하지 않고 조정 거래로 정정한다.
- 취소·무효 시 정책상 차감 사유가 없다면 예치 자산을 원래 사용자에게 반환한다.
- 한 경기에서 예치한 양은 이전, 반환, 소각 중 명시된 거래의 합과 같아야 한다.
- 경기 기능이 Division 문서에 없는 새 학습일수를 발행해서는 안 된다.
- 1대1 정산 트랜잭션은 MMR, MMR 이력, MMR 표시 티어와 MMR 표시용 `rankPoint`를 쓰지 않는다.
- 도전자 승리 시 Arena 랭크·순위·GP 세 필드가 모두 교환되거나 모두 롤백되어야 한다.
- 방어자 승리 시 Arena 랭크·순위·GP에 쓰기 작업이 발생해서는 안 된다.

## 8. 부정행위와 공모

최소 탐지 항목:

- 동일 기기·네트워크·결제수단·페이백 계좌 연관 계정의 반복 경기
- 한 방향으로만 반복되는 학습일수 이전
- 비정상적으로 빠른 제출 또는 반복 무응답
- 동일 답안·고의 오답 패턴
- 특정 상대와의 반복 No-show
- 매칭 후 상대 교체 또는 클라이언트 파라미터 조작

의심 경기의 기본 흐름:

```text
NORMAL → 자동 정산
SUSPICIOUS → HELD
CONFIRMED → 정산
INVALID → 참가자 잠금 해제·예치분 반환 또는 조정 거래
```

특정 사용자의 페이백을 임의로 통제하기 위해 문제 난이도, 상대 가중치 또는 판정을 비공개로 조작하지 않는다.

## 9. 취소·No-show·장애

확정된 공통 처리:

| 상황 | 처리 |
|---|---|
| 적격 상대 없음 | 학습일수 예치 없이 종료 |
| 서버 장애 | 경기 무효·참가자 잠금 해제·예치분 반환 |
| 문제 오류 | `HELD` 후 재채점 또는 무효 |
| 결과 미확정 상태에서 평가일 도달 | 페이백 심사 보류 또는 서버 책임 취소 |
| 정지·탈퇴·결제 분쟁 | 원인과 시점에 따라 hold 또는 무효 |
| Main 방어 일정 보호권 정상 사용 | 문제 팩 열람 전 `INSURED_CANCELLED`·공식 승패·실적 없음·양측 예치분 반환·공격자 1일 보상·최근 상대 제외와 어뷰징 탐지에는 포함 |

일반 쟁탈전 참가자는 공식 매치 성립 뒤 24시간 안에 시작해야 한다. 복수전은 신청 시 상대가 자동 참가하고 양측 모두 24시간 안에 문제 풀이를 완료해야 한다. 두 Division 모두 시작·완료 마감은 일요일 14:30을 넘길 수 없다. 아직 매치가 성립되지 않은 Main 하위 티어 초대 예약에는 고정 24시간 만료를 적용하지 않는다. 미시작·미완료 사용자는 `noShowRole`로 기록하고 운영자 알림을 생성한다. 복수전 상대방 No-show 정산은 각 Division 문서를 따른다.

## 10. 비경쟁 결과 확장 기능

배지, 시즌 기록과 Arena Feed는 학습일수를 발행하거나 경기 결과를 바꾸지 않는 기능으로 둔다. Main 전용 프로필 장식과 편의 아이템은 [`12_SHOP.md`](./12_SHOP.md)의 가격·소각·복구 정책을 따를 때만 학습일수로 구매할 수 있다. Sub Division에는 상점을 제공하지 않는다.

- 이벤트 재처리로 배지가 중복 지급되지 않아야 한다.
- 결과 취소·정정 시 취소 또는 조정 이벤트를 남긴다.
- 비경제적 보상이 Sub 학습일수나 페이백 자격을 생성해서는 안 된다.
- Main Division 일반 상향 공격과 하위 티어 초대전은 정책 버전에 고정된 티어 차이별 최소 예치, 서버 무작위 상대 선정과 초대 예약을 사용한다. 복수전은 공통 문제·판정 규칙과 Division별 경제 스냅샷을 함께 고정한다.
- `방어 일정 보호권`은 정상 경기 결과를 수정하는 아이템이 아니라, 문제 팩 열람 전 의무 방어 경기를 승패 없이 취소하는 Main 전용 예외다.

# GOAT Arena 공통 1대1 경기 규칙

> 상태: Division 공통 기반  
> 우선순위: 각 Division 최종 규칙보다 낮음  
> Unranked 전용 수치·정산: [`03_SUB_DIVISION_RANKING_SYSTEM_PAYBACK.md`](./03_SUB_DIVISION_RANKING_SYSTEM_PAYBACK.md)
> Ranked 전용 규칙: [`04_MAIN_DIVISION_RANKING_SYSTEM.md`](./04_MAIN_DIVISION_RANKING_SYSTEM.md)
> Ranked 전용 상점: [`12_SHOP.md`](./12_SHOP.md)

이 문서는 Unranked와 Ranked가 함께 사용하는 경기 진행, 문제 공정성, 서버 판정, 기록 원칙을 정의한다. 공격 대상, 예치·복수전 경제와 페이백 수치는 Division 문서에서 정한다. 복수전의 문제·채점·증거·승패 판정은 공통이지만 예치와 No-show 정산은 Unranked와 Ranked가 서로 다르다. 모든 1대1 경기의 MMR 분리와 Arena 상태 교환 원칙은 이 문서의 공통 불변식으로 적용한다.

## 1. Division 분리 원칙

- Unranked와 Ranked는 참가자 풀, 랭킹, 경제 자산과 정책 버전을 분리한다.
- 서로 다른 Division 사용자는 공식 랭킹 경기에서 만나지 않는다.
- Unranked 자산이나 결과를 Ranked 규칙에 임의로 전환하지 않는다.
- Ranked 진입 여부는 Unranked 평가 결과일 수 있지만, 진입 후 Ranked 경기 규칙을 뜻하지 않는다.
- 클라이언트가 보낸 Division, 상대, 예치 자산(페이백 점수 또는 학습일수), 랭크를 권위 값으로 신뢰하지 않는다.

## 1.1 모든 1대1 경기의 MMR 분리 불변식

일반 1대1과 복수전은 MMR과 완전히 분리한다.

```text
MMR
= 배치고사 및 매주 일요일 공식 모의고사에서만 변경

Arena 상태
= Arena 랭크 + Arena 랭크 내 순위 + Arena GP
```

1대1 서비스는 다음 목적으로 MMR을 읽거나 사용하지 않는다.

- 상대 후보 선정
- 공격 자격 또는 방어 자격
- 문제 난이도 배정
- 승패 판정
- 타이브레이커
- Arena 상태 교환 여부
- 학습일수 정산
- 일일 공격·방어 상한

### 도전자가 승리한 경우

두 사용자의 Arena 상태 3종을 한 묶음으로 통째로 교환한다.

```text
swap(challenger.arenaRank, defender.arenaRank)
swap(challenger.arenaPosition, defender.arenaPosition)
swap(challenger.arenaGp, defender.arenaGp)
```

도전자는 방어자가 경기 전에 보유한 Arena 랭크·순위·GP를 모두 받고,
방어자는 도전자가 경기 전에 보유한 Arena 랭크·순위·GP를 모두 받는다.

### 방어자가 승리한 경우

```text
Arena 랭크 교환 없음
Arena 순위 교환 없음
Arena GP 교환 없음
MMR 변경 없음
```

학습일수 정산만 Division 정책에 따라 수행한다.

### MMR 변경 경로

배치고사와 Matths 주간 공식 모의고사 정산만 MMR을 변경한다. Matths 주간 공식 모의고사 이용권 사용자는 배치고사 없이도 주간 공식 모의고사로 MMR 시계열을 먼저 만들 수 있지만, 이 값만으로 GOAT Arena에 입장하거나 Arena 상태를 받을 수 없다.

일요일 공식 모의고사로 갱신된 MMR은 Final Ranking의 핵심 입력으로 사용한다.
Final Rating 계산은 Unranked·Ranked 성과를 읽기만 하며,
Arena GP 또는 Arena 랭크·순위를 변경하지 않는다.
해당 작업은 1대1 Match 정산과 분리된 별도 정책·이벤트·트랜잭션으로 처리한다.

## 1.2 Final Ranking과 1대1의 경계

Final Ranking은 1대1 경기의 입력이나 정산 결과가 아니다.

- Final Rating으로 상대를 배정하지 않는다.
- Final Rank로 문제 난이도를 바꾸지 않는다.
- 1대1 결과 직후 Final Rating에 보너스를 누적하지 않는다.
- 정산된 Arena 상태 변화가 있으면 Final Rating을 공식으로 실시간 재계산한다.
- Division 기본점수와 성장·위치점수는 매번 덮어쓰며 중복 누적하지 않는다.
- Final Ranking은 Skill MMR과 Division 성과를 권위 입력으로 다시 계산하되, 그 계산 결과로 Skill MMR이나 Arena 랭크·순위·GP를 변경하지 않는다.

자세한 공식은
[`08_FINAL_RANKING_SYSTEM.md`](./08_FINAL_RANKING_SYSTEM.md)를 따른다.

## 1.3 구독·학습권 기반 경기 자격

공식 1대1 참가자는 다음을 모두 만족해야 한다.

`Matths 주간 공식 모의고사 이용권`은 이 조건의 유료 학습권 패키지로 취급하지 않는다. 해당 상품은 Matths 주간 공식 모의고사만 허용하며 배치고사와 GOAT Arena 일반 쟁탈전·복수전을 모두 차단한다.

```text
currentSeasonPlacementCompleted = true
AND accountStatus = ACTIVE
AND availableLearningDays > 0
AND accessState = PAID_ACTIVE
AND sundayDivisionLock = false
```

Unranked는 정기권 학습 가능 일수가 0이 되면 공격·방어·복수전과 신규 매칭을 즉시 중단한다. Ranked 상향 쟁탈전은 예치하는 공격자가 `availableLearningDays > stakeDays`, 자동 방어자가 `availableLearningDays > 0`을 만족해야 한다. 수락형 하위 티어 초대전은 양측이 `availableLearningDays > stakeDays`를 만족해야 한다. 사용 가능 잔액이 0이고 미성립 초대 예약이 있으면 Ranked 정책에 따라 예약을 먼저 취소·반환한다.

```text
availableLearningDays = 0
→ ACCESS_EXPIRED_LOCKED
→ defensePoolEligible = false
```

Ranked 최종 만료는 다음 조건을 모두 만족할 때만 처리한다.

```text
availableLearningDays = 0
AND reservedLearningDays = 0
AND lockedLearningDays = 0
AND noPendingSettlement
```

만료 사용자는 무료 방어자로 남지 않는다.

진행 중 경기의 예치 학습권이 남아 있으면 정산을 우선하고,
정산 완료 뒤 만료 상태로 전환한다.

## 1.4 재구독과 Arena 재진입

Ranked 사용자의 총 학습일수가 끝나면 Ranked 이용이 만료되고 GOAT Arena가 잠긴다.
재결제 뒤의 배치와 Unranked 재진입은 Ranked 만료·재구독 규정을 따른다.

```text
72시간 이내 재구독
→ Ranked-to-Unranked Rank Convert
→ 시험 없음

72시간 초과 재구독
→ 재구독 랭크 결정전
→ Unranked 재진입 랭크 확정
```

늦은 재구독자는 시험 최고점을 받아도
정상 72시간 내 갱신 시 받을 변환 랭크보다 높은 위치에 배치할 수 없다.

`재구독 랭크 결정전`은 Skill MMR 배치고사가 아니라
Unranked Arena 재진입 Seed를 결정하는 시험이다.

## 2. 공통 경기 생명주기

```text
자격 확인
→ 상대 후보 결정
→ 정책 버전·경기 조건 고정
→ 문제 자동 생성·검산·봉인
→ Division별 필요 자산(페이백 점수 또는 학습일수) 예치와 양측 READY 생성
→ 양측 응시·답안 저장
→ 서버 채점
→ 무결성 검사
→ 결과 확정 또는 보류
→ Arena 상태·자산·통계를 원자적으로 정산
→ 알림·기록 이벤트 발행
```

권장 상태:

```text
REQUESTED
→ MATCHED
→ READY
→ IN_PROGRESS
→ SUBMITTED
→ RESOLVED | HELD | INVALID
→ SETTLED | CANCELLED | INSURED_CANCELLED
```

- 한 사용자는 같은 시점에 정산되지 않은 공식 경기를 하나만 가진다.
- `HELD` 상태에서는 Arena 상태와 해당 Division의 예치 자산을 확정하지 않는다.
- 이미 `SETTLED`된 경기는 같은 요청이 다시 와도 재정산하지 않는다.
- 경기 시작 시점의 `PolicyVersion`과 문제·채점 버전을 끝까지 유지한다.

## 2.1 일요일 공통 신규 경기 마감과 공통 잠금

Unranked와 Ranked는 매주 일요일 14:00부터 신규 경기 신청·수락·준비·시작을 차단한다.
Ranked의 일반 상향 공격 매칭, 하위 티어 초대 수락·매치 성립과 복수전 신청·수락·시작도 같은 14:00 마감을 적용한다.
진행 중 경기는 15:00 전에 답안·풀이 증거 제출과 정산을 끝내야 하며,
15:00부터 월요일 00:00까지 Unranked와 Ranked에 진행 중인 공식 1대1 경기가 없어야 한다.

잠금 대상:

- 일반 공격·방어 매칭
- 복수전 신청·수락·시작
- Arena 상태를 변경할 수 있는 공식 정산

```text
subNewMatchRequestCutoff = Sunday 14:00
mainNewMatchRequestCutoff = Sunday 14:00
arenaWriteLock = Sunday 15:00
```

15:00까지 정산되지 않은 예외 경기는 `HELD` 처리하며
일요일 Division 스냅샷을 변경하지 않는다.

잠금 중 공개 Final Ranking은 15:00 상태로 고정한다. 정상 이용자의 공식 모의고사 MMR과 Weekly Mock Bonus, 새 Final Rank는 staging에서 계산한 뒤 월요일 00:00에 Arena 잠금 해제와 함께 일괄 공개한다. 학습권 만료 사용자는 시험과 staging 대상에서 제외한다.

## 2.2 Unranked 일반 쟁탈전 생성

현재 구현된 최초 생성 범위는 다음과 같다.

```text
신청자 자격 확인
→ 같은 활성 Unranked의 적격 방어자 조회
→ 같은 티어의 더 높은 순위 후보를 우선 구성
→ 후보가 없을 때만 바로 위 티어 후보로 한 단계 확장
→ 서버가 공정 배분 후보 중 한 명을 무작위 선정·재검증
→ 공격자 적용 일수 예치
→ 양쪽 참가자 공식 경기 잠금
→ 자동 봉인 문제·READY 경기·양쪽 응시·원장·이벤트 생성
```

- 사용자는 상대 개인과 목표 티어를 고르지 않는다. 서버가 순위 사다리 규칙으로 목표 범위를 확정한다.
- 모든 티어에서 먼저 도전자와 같은 티어이면서 도전자보다 `arenaPosition`이 높은 적격 방어자를 찾는다. 후보가 한 명이라도 있으면 바로 위 티어로 확장하지 않는다.
- 같은 티어의 상위 후보가 없을 때만 정확히 바로 위 티어에서 다시 찾는다. 두 단계 이상 위로는 확장하지 않으며 챌린저는 같은 챌린저의 더 높은 순위만 대상으로 삼는다.
- 각 티어의 절대 최하위 사용자는 별도 방어 예외를 받지 않는다. 공격으로 순위를 높인 뒤 자신보다 아래 순위가 생겨야 같은 티어 자동 방어 후보가 된다.
- 상대가 배정되기 전에는 개인 후보 목록과 닉네임을 공개하지 않는다. 매치가 성립한 뒤 경기 화면에는 서비스 닉네임만 표시하며 실명·학교·지역·연락처는 공개하지 않는다.
- 후보 정렬 순서는 서버 내부 선별에만 사용하고 개인 후보 목록은 사용자 화면에 표시하지 않는다.
- 내부 실력 지표와 최종 종합 랭킹은 후보 선정에 사용하지 않는다.
- 서버가 선정한 상대의 순위 문서는 현재 시즌·사용자·접근 상태·이용 주기와 트랜잭션 안에서 다시 대조한다.
- 적격 상대가 없으면 경기·참가자 잠금·페이백 점수 또는 학습일수 예치 원장을 만들지 않는다.
- Unranked 일반 쟁탈전은 전 이용 주기에 페이백 점수 1점 고정값을 적용한다.
- 일반 쟁탈전 생성 시 Division별 장부를 분리해 예치한다. Unranked는 공격자의 페이백 점수 1점만 예치하고 방어자는 점수를 예치하지 않는다. Ranked 상향 쟁탈전은 공격자의 학습일수만 예치하며, Ranked 하위 티어 초대전은 수락 시 양측이 같은 학습일수를 예치한다.
- 공격자와 방어자 모두 참가자 잠금을 얻어 한 시점에 미정산 공식 경기 하나만 가질 수 있다.
- 요청 식별자 재전송은 같은 경기로 응답하고 예치 자산·원장·이벤트를 중복 생성하지 않는다.
- 경기 요청 뒤 양측은 24시간 안에 시작해야 한다. 단, 일요일을 통과하는 요청의 시작 마감은 24시간보다 이른 일요일 14:00이다.
- 일요일 14:00부터 월요일 00:00까지 신규 경기 생성을 차단한다.
- 일반 경기에서 공격자만 시작하지 않으면 방어자 자동 승리, 방어자만 시작하지 않으면 공격자 자동 승리로 정산한다. 양측 모두 시작하지 않으면 승패·복수전 권리 없이 `CANCELLED`로 취소하고, 실제 예치된 페이백 점수·학습일수는 각 원래 이용 주기에 전액 반환한다.
- 서버가 자동 배정한 방어전을 방어자가 시작하지 않은 기록은 경기당 한 번만 누적한다. 5회가 되면 Unranked·Ranked 공통으로 자동 방어 후보에서 제외하지만 학습일수 일일 차감은 계속한다. 해당 사용자가 참가 가능한 공격을 한 번 정상적으로 생성하면 누적을 0으로 초기화하고 자동 방어 후보 자격을 복구한다. 자발적으로 수락한 Ranked 하위 티어 초대전과 복수전 미응시는 이 자동 배정 방어 누적에 포함하지 않는다.
- 동시 요청은 트랜잭션과 사용자별 고유 참가자 잠금으로 직렬화한다. 같은 사용자를 대상으로 경합한 요청 중 하나만 공식 경기로 확정하고, 나머지 요청은 예치·문제 팩·순위 변경 없이 충돌 응답으로 종료한다.
- 신청 순간 두 사용자의 티어 조합을 고정하고 Division·방어자 티어 기준 Unranked `U1~U9`, Ranked `R1~R9` 문제 5문항을 자동 생성·자동 검산한다. 2016~2026 EBSi 고3 전월 모의고사 전 문항의 출제 의도와 자체분석 정답률을 결합해 기초 일반·일반·상위 일반·준킬러·킬러를 분류한다. 낮은 티어는 일반 문항 중심, 플래티넘부터 준킬러, 마스터부터 킬러를 단계적으로 섞는다. 생성된 팩은 공개 난이도 코드·문제 데이터 버전 ID·콘텐츠 버전·문항·정답·해시를 함께 봉인하므로 이후 관리자 변경이 진행 중 경기에 소급되지 않는다. 유형 누락이나 자동 검산 실패 시에는 해당 경기의 페이백 점수 또는 학습일수를 예치하기 전에 신청을 거절한다.

## 2.3 문제 팩 배정과 양측 응시

현재 구현 범위는 다음과 같다.

```text
경기 신청 트랜잭션
→ 티어 조합별 문제 즉시 생성·자동 검산·봉인
→ 같은 문제·배점·제한 시간·채점 버전 고정
→ 양쪽 READY 응시 문서 생성
→ 참가자가 각자 시작하면 IN_PROGRESS
→ 답안 변경·heartbeat·focus 이벤트 서버 저장
→ 수동 제출 또는 제한 시간 자동 제출
→ 양쪽 제출 완료 시 경기 SUBMITTED
```

- 실제 경기에는 자동 검산을 통과하고 콘텐츠 해시가 고정된 `SEALED` 문제 팩만 배정한다.
- 문제 팩은 총점 100점이며 각 문항은 최대 10분의 개별 제한시간을 가진다. 티어별 5문항 구성은 3절의 객관 정답률 사다리를 따르며 두 사용자에게는 같은 문제가 제공된다.
- GOAT Arena 1대1은 평가센터 유형 풀을 사용하지 않는다. 새 D1~D9 PDF 스켈레톤 풀은 Arena 전용 카탈로그로만 준비하며 명시적 활성화 전에는 실제 경기에 연결하지 않는다.
- 문제 난이도는 두 사용자에게 완전히 같다. Unranked는 방어자 티어를 `U1~U9`, Ranked는 방어자 티어를 `R1~R9`로 표시하고 같은 숫자의 U/R은 동일한 티어 난이도 구성을 사용한다. 기존 DB의 `T1~T9`는 콘텐츠 카탈로그 호환용 내부 키일 뿐 사용자 화면과 규정에는 노출하지 않는다.
- 운영자 수동 문제 검수는 요구하지 않는다. JS 생성기와 검산기가 해답 일치·유일답·계산기 불필요·풀이 가능 여부를 모두 통과시켜야 한다.
- 봉인 시 문항·정답·해설·배점·난이도·제한 시간·채점 버전 전체의 해시를 저장하며 배정할 때 서버가 다시 검증한다.
- 두 참가자는 동시에 접속할 필요가 없다. 각 참가자가 시작한 서버 시각부터 같은 길이의 개인 제한 시간이 흐르며 화면을 닫아도 멈추지 않는다.
- 정답과 해설은 참가자 응답에 포함하지 않는다.
- 한 화면에는 현재 문항 하나만 표시한다. `다음 문제`를 누르면 답을 확정하고 이전 문항의 내용·답안을 다시 열람하거나 수정할 수 없다.
- 5번 문항에서 다음 버튼을 누르거나 10분이 끝나면 문제 화면을 즉시 닫고 1분 풀이 증거 제출 화면으로 전환한다.
- 풀이 증거는 양측 모두 사진 1~5장을 서버에 60초 안에 업로드 완료해야 하며 상대에게 공개하지 않는다.
- 필수 풀이 증거를 기한 안에 내지 않은 사용자는 자동 패배한다. 이는 운영자가 별도로 요청할 수 있는 추가 소명 자료와 다르며, 필수 증거 미제출에 추가 소명 유예는 적용하지 않는다. 양측 모두 필수 증거를 내지 않으면 승패 없이 취소하고 예치분을 원상 반환한다.
- 운영자는 모든 경기 증거를 관리자 화면에서 열람할 수 있고, 동일 파일·비정상적으로 빠른 풀이·반복 화면 이탈 등 이상 징후는 자동 알림으로 받는다.
- heartbeat와 focus 이벤트의 클라이언트 시각은 참고값으로만 저장하고 서버 수신 시각을 함께 남긴다. 유효 풀이시간 계산은 후속 판정 단계에서 수행한다.
- 시작·답안 저장·활동 기록·제출은 요청 식별자로 멱등 처리한다.
- 제한 시간이 끝난 미제출 응시는 서버 작업이 마지막 저장 답안으로 자동 제출한다.
- 새로고침·탭 종료·일시적 네트워크 단절은 서버의 문항·답안·제한시간을 초기화하지 않는다. 재접속하면 동일한 현재 문항만 복구하며, 사용자가 돌아오지 않아 마지막 문항과 필수 증거 제출을 끝내지 못하면 위 자동 판정을 적용한다.
- 브라우저 보안상 새 탭을 만들었다는 행위 자체나 이동한 사이트 주소는 읽지 않는다. 다만 응시 탭에서 새 탭·다른 창·다른 앱으로 이동할 때 발생하는 `visibilitychange`·창 포커스 이탈을 활동 기록으로 전송하며, 페이지 종료 시 `pagehide`에서도 마지막 신호를 keepalive 방식으로 보낸다. 한 번의 화면 이탈에서 함께 발생한 중복 브라우저 이벤트는 클라이언트에서 합쳐 기록한다.
- Unranked와 Ranked 모두 일요일 14:00 이후 새 경기 준비·시작을 허용하지 않는다. 두 Division 모두 15:00부터 답안 변경·활동 기록·제출과 자동 제출을 진행하지 않으며 예외 미정산 경기는 `HELD`로 보낸다.
- 한 명만 제출한 동안 경기는 `IN_PROGRESS`를 유지하고, 양쪽이 모두 제출하면 `SUBMITTED`가 된다.
- 증거 제출 시 3자리 이하 자연수 답을 서버에서 채점해 개인 점수·정답 수를 저장한다. 양측 증거와 무결성 확인이 끝나면 해당 Division의 확정 정산표에 따라 승패, GP·티어·티어 내 순위와 정기권 학습 가능 일수를 한 트랜잭션으로 반영한다.

|---|---:|---:|---|
| 브론즈 | U1 | R1 | U는 준킬러 5문항, R은 준킬러 4문항 + 킬러 1문항 |
| 실버 | U2 | R2 | 같은 숫자의 R등급이 U등급보다 어려움 |
| 골드 | U3 | R3 | 같은 숫자의 R등급이 U등급보다 어려움 |
| 플래티넘 | U4 | R4 | 같은 숫자의 R등급이 U등급보다 어려움 |
| 에메랄드 | U5 | R5 | 같은 숫자의 R등급이 U등급보다 어려움 |
| 다이아몬드 | U6 | R6 | 같은 숫자의 R등급이 U등급보다 어려움 |
| 마스터 | U7 | R7 | 양 Division 모두 5문항 전부 29·30번형 킬러 |

Ranked에서 티어 차이가 2~3단계여도 방어자 티어가 같으면 같은 R등급을 사용한다. 기존 DB의 `T1~T9`는 콘텐츠 묶음을 재사용하기 위한 내부 카탈로그 키로만 남긴다.

- R1~R6은 `쉬운 준킬러 → 준킬러 → 어려운 준킬러 → 최상위 준킬러 → 킬러` 순으로 상승시킨다. R5의 기준 예시는 `25~26% → 23~25% → 21~23% → 20~22% → 4~6%`다.
- U7~U9와 R7~R9은 1~5번을 모두 29·30번형 킬러로 구성하며, 같은 등급 안에서도 뒤 문항으로 갈수록 목표 정답률을 낮춘다.
- U1에서 U9, R1에서 R9로 갈수록 목표 정답률이 낮아지며 같은 번호에서는 R등급이 U등급보다 어렵다.

### 3.3 준킬러 정의와 고정 경기 규격

```text
U1~U6 = 준킬러 5문항
R1~R6 = 준킬러 4문항 + 29·30번형 킬러 1문항
U7~U9·R7~R9 = 29·30번형 킬러 5문항
배점 = 문항당 20점, 총 100점
제한 시간 = 문항당 최대 10분
문제 = 양측 완전 동일
답 = 1~999 자연수 주관식
```

준킬러는 통상 정답률 10~30%대의 중상 난도 문항으로, 개념 2개 이상을 결합하고 조건을 최소 한 단계 변형해야 식이 나온다. 개념 하나를 직접 대입해 끝나는 워밍업 문항은 U1에도 넣지 않는다. U1~U6의 5번과 R1~R6의 1~4번은 준킬러 범위에 남긴다. R1~R6의 5번과 U7~U9·R7~R9의 전 문항은 29·30번형 다중 조건 킬러 생성기와 독립 풀이 검산을 통과해야 한다. 답은 현재 문항에서 다음 버튼을 누르기 전까지만 변경할 수 있고, 다음 문항으로 이동한 뒤에는 직전 문제의 답과 문제 내용을 다시 볼 수 없다.

| Unranked 등급 | 개념 결합 | 조건 수 | 해석 깊이 | 경우분류 |
|---|---:|---:|---:|---:|
| U1 | 2 | 1 | 직접 | 0 |
| U2 | 2 | 1 | 직접 | 1 |
| U3 | 2 | 2 | 1단계 | 1 |
| U4 | 2 | 2 | 1단계 | 2 |
| U5 | 2~3 | 2 | 1단계 | 2 |
| U6 | 3 | 2 | 2단계 | 3 |
| U7 | 3 | 2~3 | 2단계 | 3 |
| U8 | 3 | 3 | 2단계 | 3 |
| U9 | 3 | 3 | 2단계 | 4 |

계산량은 U1~U9·R1~R9 모두 계산기 없이 풀 수 있는 범위로 제한한다. 상위 등급의 난이도는 무의미한 산술량이 아니라 조건 해석 깊이, 경우분류와 개념 결합에서 만든다. Ranked는 같은 공개 번호의 Unranked보다 조건 결합과 경우분류 부담을 높인다.

그래프·표·도식은 난이도를 낮추거나 풀이 힌트를 주기 위해 강제로 넣지 않는다. 문제 본문 자체가 해당 자료를 제시하는 유형이고 생성기가 정확한 식·함수 라벨·점·좌표·보조선 데이터를 함께 제공한 경우에만 흰색 문제지 안에 렌더링한다. 풀이과정에서 그래프를 그리면 편하다는 이유만으로 문제 화면에 그래프를 추가하지 않는다.

### 3.5 5문항 팩 구성

- 기본 곡선: `하단 / 중심 / 중심 / 중심~상단 / 상단`
- 챌린저→챌린저: `중심 / 중심 / 상단 / 상단 / 상단`
- 직접 출제 범위: 대수, 확률과 통계, 미적분Ⅰ
- 기초 연계 범위: 공통수학Ⅰ·Ⅱ의 위계·연계 개념. 현재 실전 5슬롯에 공통수학Ⅰ·Ⅱ를 독립 과목으로 배정하지 않는다.
- U1~U6 1~5번: 13·14·20·21·27·28번 4점형 준킬러 사고 구조를 티어에 맞게 재구성
- R1~R6 1~4번: 같은 숫자의 U등급보다 어려운 준킬러를 배정
- R1~R6 5번: 실제 29·30번형 다중 조건 킬러를 의무 배정
- U7~U9·R7~R9 1~5번: 실제 29·30번형 다중 조건 킬러를 의무 배정
- 같은 유형은 한 경기 안에서 중복하지 않음
- 그래프·표·도식 수를 강제하지 않으며 문제 본문에 실제로 제시된 자료만 표시
- 양쪽 참가자의 최근 공식 경기 5개에 사용한 공개 유형 ID와 실제 생성 유형을 먼저 제외하고, 후보가 부족할 때만 오래된 유형부터 다시 사용
- 같은 경기 안에서는 공개 유형·원형 유형·실제 생성기 모두 중복 금지

현재 활성 생성기는 5문항 각각의 수치를 생성한 뒤 유형별 독립 풀이·계산기 불필요·1~999 자연수 답을 검증한다. 그 다음 팩 단위에서 서로 다른 5개 유형과 서로 다른 5개 생성기, Division별 5번 문항 배정을 다시 검증한다. 그래프·표·도식이 문제 본문에 실제 제시된 문항은 생성 수치와 함께 문제팩에 봉인하고, 식·함수 이름·점·좌표·보조선·음영 영역까지 같은 흰색 문제지 안에 렌더링한다. 공개 난이도 18개마다 최소 30개 수치·조건 변형 유형을 두며, 실제 숫자 생성과 독립 검산이 구현된 유형만 ACTIVE DB 카탈로그를 통해 경기 출제를 허용한다. 분류 골격이 있다는 이유만으로 미구현 생성 유형을 실전에 사용하지 않는다.

### 3.7 문항·팩 검수

문항 하나마다 다음을 모두 확인한다.

- 개념 2개 이상 결합 + 조건 한 단계 이상 변형
- 유일한 답, 1~999 자연수, 대수·확률과 통계·미적분Ⅰ 직접 출제 범위와 공통수학Ⅰ·Ⅱ 기초 연계 범위
- 누락·충돌 조건 없음, 독립 계산한 풀이와 답 일치
- 표시 티어와 풀이 부담 일치, 문항당 10분 안에 계산기 없이 풀이 가능
- 계산량이 아니라 논리에서 난이도가 발생
- 기출·자체 문항의 과도한 복제 금지

팩 단위로는 Division·공개 난이도별 준킬러·킬러 구성, 서로 다른 공개 유형·원형 유형·실제 생성기, 티어 내 난이도 곡선, 양쪽 참가자 최근 공식 경기 5개 유형 우선 제외와 `FINAL_29_30` 슬롯 배정을 검증한다. 문항 생성은 숫자를 바꾼 뒤 생성기와 독립 풀이기가 각각 답을 계산하고 두 결과가 같을 때만 출제한다. 그래프 문항으로 표시된 문항은 문제 본문이 해당 그래프를 명시하고 렌더 가능한 시각화 데이터와 라벨·좌표·보조선이 모두 있을 때만 출제한다. 유형은행의 개념 연습용 `difficulty 1~3`을 Arena U/R 난이도에 직접 대응시키지 않는다.

### 3.8 실측 보정과 버전

문항 유형별 최소 30경기가 쌓인 뒤에만 보정한다. 모든 결과에 `PolicyVersion`을 저장해 당시 정책을 재현한다.

| 신호 | 조치 |
|---|---|
| 방어자 정답률이 목표 상단보다 8%p 초과 | 경우분류 +1 또는 그래프 제공 축소 |
| 방어자 정답률이 목표 하단보다 8%p 미만 | 조건 -1 또는 그래프 제공 확대 |
| 방어자·도전자 정답률 차가 8%p 미만 | 상단 슬롯 한 등급 상향 |
| 정답률 차가 25%p 초과 | 하단 슬롯 한 등급 하향 |
| 5문항 만점 경기 15% 초과 | 5번 슬롯 상향 |
| 무득점 경기 10% 초과 | 1번 슬롯 하향 |
| 완전 동점 20% 초과 | `하단/중심/중심/상단/상단` 곡선 검토 |

업로드 설계표의 `서든데스 발생률`은 현행 서비스에 별도 서든데스 경기가 없으므로 `완전 동점 발생률`로 측정한다. 현행 완전 동점은 방어자 승리 규칙을 유지한다.

다음 오류를 금지한다: 도전자 티어 앵커, Ranked 난이도 보정 누락, 상위 티어의 계산량만 증가, 유형은행 난이도 직접 매핑, 동일 유형 중복, 워밍업 문항, R1~R6 5번 킬러 누락, U7~U9·R7~R9 일반 문항 혼입, 풀이용 그래프를 문제 제시 그래프로 오인하는 처리.

## 3.9 복수전 권리와 진행

- 가장 최근에 끝난 원경기의 패자에게 결과 화면에서 한 번만 복수전 선택권을 준다.
- `복수하기`를 누르면 권리를 즉시 사용하고 상대는 별도 수락 없이 자동 참가한다.
- `경기 종료`를 누르거나 결과 화면에서 복수전 권리를 포기하면 같은 원경기로 다시 신청할 수 없다.
- 복수전은 원경기·권리·신청자·상대·Division 정책 버전을 고정해 한 번만 생성한다.
- 일반 경기의 최근 7일 재대결 제한은 복수전에 적용하지 않는다.
- 신청 후 24시간 안에 양측이 문제 풀이를 완료해야 하며 일요일 14:00을 넘길 수 없다.
- 문제·채점·증거 제출·Arena 상태 교환 기준은 일반 쟁탈전과 같고, 예치·수수료·No-show 반환·소각량만 Division 문서를 따른다.
- 복수전 신청자가 미완료하면 방어자 승리로 처리하고 Arena 상태는 교환하지 않으며, 신청자가 예치한 페이백 점수 또는 학습일수는 해당 Division 정산 정책에 따라 처리한다.

## 4. 승패 판정

현재 채점 단계는 각 참가자에게 다음 값을 계산해 저장한다.

```text
score
correctCount
correctAnswerSolveTimeMs
totalSolveTimeMs
```

- 점수와 정답 성과가 시간보다 우선한다.
- 브라우저가 보낸 시간 숫자를 그대로 사용하지 않는다.
- 서버 시각, heartbeat, focus 이벤트와 네트워크 유예 정책으로 유효 풀이시간을 산정한다.
- 문제 오류나 서버 장애로 공정한 판정이 불가능하면 방어자 승리로 강제하지 않고 `HELD` 또는 `INVALID`로 보낸다.
- 승패 우선순위는 `점수 높은 순 → 정답 수 많은 순 → 정답 문항 풀이시간 짧은 순 → 전체 풀이시간 짧은 순`이다.
- 네 값이 모두 같으면 방어자 승리로 처리한다. Ranked도 같은 순서를 사용한다.

Sudden Death는 현재 정책에 포함하지 않는다.

## 5. 익명성과 개인정보

- 자동 상대 선정 전에는 개인 후보를 공개하지 않는다.
- 실명, 학교, 지역, 연락처, 결제 정보와 공모 탐지 신호는 공개하지 않는다.
- 매치 성립 뒤에는 상대의 서비스 닉네임과 경기상 필요한 Arena 정보만 표시한다. 정산 뒤 내 전적에서는 공개 프로필·경기 당시 Division·티어·GP·순위를 함께 확인할 수 있다. 실명·학교·지역·연락처·결제 정보는 공개하지 않는다.
- 탈퇴 사용자의 과거 경기·랭킹 이력은 운영상 필요한 기록을 유지하되 공개 화면에서는 익명화한다.

Unranked와 Ranked는 위 공개 범위를 공통 최소 기준으로 적용한다. Division별 추가 공개 항목은 명시적으로 확정된 정책 버전에 있을 때만 제공한다.

## 6. 서버 권위와 멱등성

서버가 직접 계산하거나 재검증해야 하는 값:

- 계정·결제주기·Division 참가 자격
- 상대 후보와 재매칭 제한
- 현재 Arena 랭크·Arena 순위·Arena GP와 당일 사용 횟수
- Division별 예치 자산(페이백 점수 또는 학습일수)과 사용 가능 잔액
- 문제 팩과 채점 정책
- 시작·종료 시각과 유효 풀이시간
- 승패, Arena 상태 3종의 교환 여부, 이전·반환·소각량
- 연속 학습, 페이백 점수와 무결성 자격

다음 동작은 고유 멱등 키를 사용한다.

```text
challenge request
match start
answer save
submission
settlement
ledger transaction
notification/outbox event
```

## 7. 정산 공통 불변식

- 모든 페이백 점수·학습일수 변화는 불변 원장 거래로 설명할 수 있어야 한다.
- Division별 예치 자산, 결과, Arena 상태 교환, 카운터와 원장 거래는 한 정산 트랜잭션에서 확정한다.
- 확정 원장 기록은 수정·삭제하지 않고 조정 거래로 정정한다.
- 취소·무효 시 정책상 차감 사유가 없다면 예치 자산을 원래 사용자에게 반환한다.
- 한 경기에서 예치한 양은 이전, 반환, 소각 중 명시된 거래의 합과 같아야 한다.
- 경기 기능이 Division 문서에 없는 새 페이백 점수 또는 학습일수를 발행해서는 안 된다.
- 1대1 정산 트랜잭션은 MMR, MMR 이력, MMR 표시 티어와 MMR 표시용 `rankPoint`를 쓰지 않는다.
- 도전자 승리 시 Arena 랭크·순위·GP 세 필드가 모두 교환되거나 모두 롤백되어야 한다.
- 방어자 승리 시 Arena 랭크·순위·GP에 쓰기 작업이 발생해서는 안 된다.

## 8. 부정행위와 공모

최소 탐지 항목:

- 동일 기기·네트워크·결제수단·페이백 계좌 연관 계정의 반복 경기
- 한 방향으로만 반복되는 학습일수 이전
- 비정상적으로 빠른 제출 또는 반복 무응답
- 동일 답안·고의 오답 패턴
- 특정 상대와의 반복 No-show
- 매칭 후 상대 교체 또는 클라이언트 파라미터 조작

의심 경기의 기본 흐름:

```text
NORMAL → 자동 정산
SUSPICIOUS → HELD
CONFIRMED → 정산
INVALID → 참가자 잠금 해제·예치분 반환 또는 조정 거래
```

특정 사용자의 페이백을 임의로 통제하기 위해 문제 난이도, 상대 가중치 또는 판정을 비공개로 조작하지 않는다.

## 9. 취소·No-show·장애

확정된 공통 처리:

| 상황 | 처리 |
|---|---|
| 적격 상대 없음 | 페이백 점수·학습일수 예치 없이 종료 |
| 서버 장애 | 경기 무효·참가자 잠금 해제·예치분 반환 |
| 문제 오류 | `HELD` 후 재채점 또는 무효 |
| 결과 미확정 상태에서 평가일 도달 | 페이백 심사 보류 또는 서버 책임 취소 |
| 정지·탈퇴·결제 분쟁 | 원인과 시점에 따라 hold 또는 무효 |
| Ranked 방어 일정 보호권 정상 사용 | 문제 팩 열람 전 `INSURED_CANCELLED`·공식 승패·실적 없음·양측 예치분 반환·공격자 1일 보상·최근 상대 제외와 어뷰징 탐지에는 포함 |

일반 쟁탈전 참가자는 공식 매치 성립 뒤 24시간 안에 시작해야 한다. 복수전은 신청 시 상대가 자동 참가하고 양측 모두 24시간 안에 문제 풀이를 완료해야 한다. 두 Division 모두 시작·완료 마감은 일요일 14:00을 넘길 수 없다. 아직 매치가 성립되지 않은 Ranked 하위 티어 초대 예약에는 고정 24시간 만료를 적용하지 않는다. 일반 쟁탈전에서 공격자만 미시작이면 방어자 승리, 방어자만 미시작이면 공격자 승리, 양측 미시작이면 취소·원상 반환한다. 복수전 상대방 No-show 정산은 각 Division 문서를 따른다.

경기 경제·수수료·티어 차이·문제·채점 규칙은 경기 생성 시점의 정책 사본과 봉인된 문제 팩으로 고정한다. 정책 변경은 적용 시각 뒤에 새로 생성되는 경기부터 적용하며, 이미 진행 중인 경기에는 소급하지 않는다. 패키지 만료 시에도 진행 중인 공식 경기는 먼저 끝내고 정산한 뒤 이용 종료·강등 여부를 집계한다.

## 10. 비경쟁 결과 확장 기능

배지, 시즌 기록과 Arena Feed는 학습일수를 발행하거나 경기 결과를 바꾸지 않는 기능으로 둔다. Ranked 전용 프로필 장식과 편의 아이템은 [`12_SHOP.md`](./12_SHOP.md)의 가격·소각·복구 정책을 따를 때만 학습일수로 구매할 수 있다. Unranked에는 상점을 제공하지 않는다.

- 이벤트 재처리로 배지가 중복 지급되지 않아야 한다.
- 결과 취소·정정 시 취소 또는 조정 이벤트를 남긴다.
- 비경제적 보상이 Unranked의 정기권 학습 가능 일수나 페이백 자격을 생성해서는 안 된다.
- Ranked 일반 상향 공격은 티어 차이별 최소 1·2·3일과 공통 최대 5일, 최근 24시간 강제 방어 최소 배정 후보 우선·동률 무작위·경기 종료 뒤 6시간 유예를 사용한다. 6시간 유예는 강제 자동 방어만 막으며, 하위 티어 초대전은 유예 중에도 적격 사용자에게 알림을 보내 자발적인 수락·거절을 허용하고 양측 동일 예치 예약을 사용한다. 복수전은 공통 문제·판정 규칙과 Division별 경제 스냅샷을 함께 고정한다.
- `방어 일정 보호권`은 정상 경기 결과를 수정하는 아이템이 아니라, 문제 팩 열람 전 의무 방어 경기를 승패 없이 취소하는 Ranked 전용 예외다.

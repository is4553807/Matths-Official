# MatthS Exchange 1.0 구현 계획

MatthS Exchange는 시험별 수학 평균 점수를 예측하는 시장이다. 학생은 무료 Trading Points(TP)로 선물형 LONG·SHORT 주문을 낸다. **맵쓰 주간 모의고사**는 시험 공개와 연동하고 해당 회차를 완료한 학생이 주문할 수 있다. **실제 고1·고2·고3 모의고사와 수능**은 운영자가 입력한 회차별 일정에 따라 열며, 응시 여부나 학년으로 주문 자격을 제한하지 않는다.

두 자료에서 겹치는 규칙은 PPT를 따른다. 맵쓰 주간 시장의 개장 최소 유효 응시자 기본값은 **0명**이다. PPT의 층화 표본법과 **30분 공개 지연**을 적용하고, 재추출 주기는 1초로 설정한다. 참고 자료는 MatthS Exchange 40장 PPT 상세 기획안과 8쪽 PDF 서비스기획서다.

## 데모 화면과 운영 진입점

- 학생 대시보드 메뉴에서 **주간 모의고사** 바로 아래의 **맵쓰 Exchange**를 선택한다. 기본 경로는 `/exchange`다. 독립 화면에 주간·실제 모의고사·수능 시장 선택, 캔들·거래량, 호가창, 지정가 주문, 배점 계산기와 포지션·미체결·주문·체결·랭킹 탭을 배치한다. [Binance Futures 화면 구성 참고](https://www.binance.com/en/support/faq/detail/a784518335b0492a9ebfa4a72e1ca092)
- 운영센터의 **콘텐츠 → Exchange 선물시장**(`/admin/exchange`)에서 정규 시험과 문제지 상태, 유효 응시 수, 기본·회차별 최소 인원, 학년·연도별 실제 시험 일정과 거래 종료 일시를 관리한다. 시장별 미체결 건수·거래량·담보·최근 표본 공개 시각을 확인하고, 거래 중지·재개, 무효 및 TP 반환, 외부 시험 평균 점수 등록을 실행할 수 있다. 등록·변경·정산 결정은 운영 이력에 남는다.
- **정규 시험 미등록은 주간 시장 미개설 상태**다. 기본 최소 인원 0명은 정상 등록·공개된 시험에서 인원 조건을 없애는 설정이다. 정규 회차가 없거나 문제지 업로드 기록 또는 채점 데이터가 유효하지 않으면 주간 시장을 생성하지 않고, 서버도 주문을 거절한다. 빈 화면의 차트와 호가에는 예시 체결가를 채우지 않는다.
- 호스팅에서 `exchange.matths.kr`의 사용자 도메인·DNS·TLS를 연결한 뒤 `EXCHANGE_BASE_URL=https://exchange.matths.kr`을 설정한다. 그러면 대시보드 링크가 서브도메인 루트로 이동하고 기존 `.matths.kr` 세션을 사용한다. 설정 전에는 같은 앱의 `/exchange`로 연결한다.

## 1. 시장별 개장 일정과 주문 자격

### 맵쓰 주간 모의고사

| KST | 시험 | 선물시장 |
| --- | --- | --- |
| 시험 등록 전 | 운영자가 이번 주 정규 시험을 등록하지 않은 상태 | 시장 없음. 호가·주문·새 주차 지수 생성 없음 |
| 일요일 15:00 | 검증된 정규 시험 공개 | 같은 회차의 시장 페이지 자동 개설. 설정된 최소 인원을 충족하면 주문 접수 개시 |
| 주중 141시간 | 기존 개인 제한 시간과 주간 마감 안에서 응시·제출 | 해당 회차 유효 제출자만 신규·청산 주문 가능. 공개 Sample MPI와 호가·체결가 확인 |
| 토요일 12:00 | 답안 접수 마감 | 신규 주문·중도 청산·매칭 동시 마감. 미체결 잔량을 취소하고 예약 TP 반환 |
| 토요일 12:00 이후 | 기존 제출 후처리, 성적 검증과 해설 공개 | 전체 유효 응시 성적 대사, Settlement MPI 확정, 남은 계약 정산 |
| 다음 일요일 15:00 | 다음 주 시험이 등록돼 있으면 공개 | 다음 회차 시장 자동 개설. 학생의 확정 TP 잔액 이월 |

- 운영자는 기존 주간 모의고사 등록 화면에서 PDF와 채점 설정을 등록한다. 파일과 채점 데이터가 검증되고 `WEEKLY` 정규 회차가 공개 가능한 상태가 되면 `examId`를 고유 키로 시장을 예약한다. 원본 `releaseAt`에 공식 시험이 열렸을 때 시장을 개설한다. 업로드가 완료되기 전, CUSTOM·테스트·데모 회차, 시험 취소 상태에서는 시장이 열리지 않는다. 웹·iPad 운영 경로는 같은 원본 회차를 사용한다.
- **최소 유효 응시자 수는 운영자가 조정하는 개장 설정이며 기본값은 `0`명**이다. 기본 설정과 회차별 덮어쓰기를 지원한다. 실제 응시 집계 숫자는 서버가 계산하며, 운영 화면은 `현재 유효 응시 N명 / 개장 최소 M명`을 함께 표시한다. 관리자가 수정하는 값은 최소 기준이다.
- 개장 전에는 기준 변경을 즉시 다시 평가한다. 개장할 때 적용값과 시각을 기록한다. 개장 이후의 기본값 변경은 다음 회차에 적용하며, 열린 시장의 신규 접수를 멈추는 경우에는 별도의 운영 중지 상태를 사용한다. 기준 변경과 중지는 운영자·변경값·사유·시각을 남긴다.
- 기본값이 0이면 정규 시험 공개와 함께 시장이 열릴 수 있다. **학생 개인의 주문 자격은 이번 회차의 유효한 최종 제출**로 확인한다. 유효 제출자가 0명이면 Sample MPI는 ‘표본 수집 중’이고, 거래가격은 양쪽 주문이 처음 체결될 때 생성된다.
- 시험과 거래는 마감 시각을 포함하지 않는다. API와 주문 매칭 작업은 서버 시각으로 마감을 확인한다. 화면에는 서버 기준 남은 시간과 KST 마감을 함께 표시한다. 시험 접수와 주문 체결은 서로 다른 기록을 쓰므로 정산은 시험의 정상 후처리가 끝날 때까지 기다린다.

### 실제 모의고사와 수능

운영자 페이지의 **실제 시험 일정**에서 시행 연도와 학년 드롭다운 `고1` / `고2` / `고3`을 선택한다. 선택한 학년에 해당하는 회차 목록이 나타난다. 각 행에서 **실제 시험일**을 날짜 선택기로 지정하고 **선물시장 종료 일시(KST)**를 입력한다. `3모` 같은 회차명은 고정 라벨이고, 실제 시험일은 시행 연도마다 운영자가 입력한다.

| 학년 | 드롭다운 선택 후 표시되는 회차 | 모의고사 수학 시험 시간 | 선물시장 자동 개장 |
| --- | --- | --- | --- |
| 고1 | 3모, 6모, 9모, 10모 | 10:30–12:10 (100분) | 입력한 시험일 12:10 KST |
| 고2 | 3모, 6모, 9모, 10모 | 10:30–12:10 (100분) | 입력한 시험일 12:10 KST |
| 고3 | 3모, 5모, 6모, 7모, 9모, 10모 | 10:30–12:10 (100분) | 입력한 시험일 12:10 KST |
| 고3 | 수능 (10모 바로 아래) | — | 입력한 수능일 16:00 KST |

- 날짜를 선택하면 **개장 일시**를 자동 계산해 읽기 전용으로 보여준다. **종료 일시**는 운영자가 시·분까지 설정하고 시험일 이후 날짜도 선택할 수 있다. 예를 들어 고2 3모의 시험일을 3월 20일로 지정하면 3월 20일 12:10에 열린다. 종료 일시는 채점 집계나 평균 점수 발표 일정에 맞춰 운영자가 지정한다.
- 시험일과 종료 일시를 저장하면 시장을 예약한다. 종료 일시는 개장 시각보다 뒤여야 한다. 날짜를 등록하지 않은 회차는 시장을 예약하지 않는다. 개장 전에는 시험일을 바꿀 수 있고, 개장 뒤에도 종료 전까지 종료 일시를 수정할 수 있다. 종료 일시 변경은 주문·체결과 같은 시장 상태 갱신을 사용해 새 마감 시각을 일관되게 적용하고 변경 이력을 기록한다. 마감된 시장은 정산 대기로 전환한다.
- 같은 날 고1·고2·고3 시험이 열리면 회차마다 별도의 시장·호가창·캔들·정산값을 만든다. 수능은 고3 목록에 표시하고 자체 회차로 저장한다. 실제 시험 시장은 **시험 응시·답안 제출·성적 인증·계정 학년 조건 없이** 주문할 수 있다. 주문 계정과 가용 TP 같은 공통 주문 요건은 적용한다.
- 맵쓰 시험 파일 등록 여부와 최소 응시자 설정은 주간 시장에 적용한다. 실제 시험 시장은 운영자가 저장한 일정으로 개장하며, 서버가 KST 개장·종료 일시를 UTC로 변환해 보관한다. 거래는 개장 시각을 포함하고 종료 시각부터 차단한다.

## 2. 화면에 표시하는 세 값

| 이름 | 정의 | 언제 달라지는가 |
| --- | --- | --- |
| **Math Index / Sample MPI** | 같은 주 시험의 등급별 표본으로 추정한 평균 원점수 × 10 | 서버가 매초 재추출하고 30분 뒤 공개한다. 표본 평균이 같으면 지수도 같은 값일 수 있다. |
| **Futures Price / 선물 체결가** | 호가창에서 매수·매도가 실제로 맞아 거래된 최근 가격 | 실제 체결에 따라 갱신한다. 첫 체결 전에는 가격이 비어 있다. |
| **Settlement MPI / 최종 정산 지수** | 해당 회차 전체 유효 응시자의 평균 원점수 × 10 | 시험 마감 뒤 원본 성적을 검증하고 시장 정산 전에 한 번 확정한다. |

Math Performance Index(MPI)는 100점 만점 원점수를 0–1,000 범위로 표시한다. 평균 원점수 65.1점은 MPI 651이다. 공개 표본 평균 62점, 최근 선물 체결가 650, 확정 평균 63점은 각각 Sample MPI 620, Futures Price 650, Settlement MPI 630으로 표시한다.

실제 시험 시장은 선물 체결가와 해당 시험의 평균 원점수에 따른 Settlement MPI를 표시한다. 외부 표본 자료를 확보하기 전에는 Sample MPI를 ‘표본 데이터 없음’으로 표시한다. 맵쓰 주간 시험의 응시 성적은 해당 주간 시장의 지수에 사용한다.

## 3. 맵쓰 주간 모의고사의 매초 Math Index 샘플링

### 모집단과 사전 MMR

- 모집단은 해당 정규 시험의 **전체 유효 응시자**다. Exchange 가입·주문·포지션 여부와 관계없이 집계 대상에 포함한다. 기존 `PrivateMockExamAttempt`에서 해당 `examId`, 서버 접수 시각, 후처리 완료, 원점수 `score`, 무결성 상태를 확인한다.
- 중복·데모·만료·임시저장 기록은 제외한다. 기존 무결성 기준에 따라 `NOT_REVIEWED`·`CLEAR`는 포함하고 `PENDING_INTEGRITY_REVIEW`는 보류하며 `INVALIDATED`는 제외한다. 시도당 한 번만 집계한다. 제출이 검토 상태에서 유효 상태로 바뀌면 그 이후의 공개용 샘플 모집단에 반영한다.
- 시험 전 MMR을 **9개 등급**에 매핑한다. 시험 시작 전에 등급을 스냅샷으로 저장하고 현재 회차 성적·주문에 따라 바꾸지 않는다. 기존 맵쓰의 평가값을 읽는 어댑터를 사용한다. PPT가 수치 경계와 미배치 학생 처리 방식을 지정하지 않았으므로 9등급 매핑과 초기 MMR 적용 규칙은 버전화한다. 미배치 학생도 정해진 초기 등급에 포함하며 최종 정산 모집단에서 빠지지 않는다.

### 계산과 공개

1. 서버는 정수 초 `t`마다 해당 시각까지 확정된 유효 성적을 기준으로, 등급별 모집단 크기 `N_g`를 읽는다.
2. 응시자가 있는 각 등급에서 **10%, 최소 1명**을 균등 무작위로 비복원 추출한다. 한 초 안에서 같은 응시자를 중복 추출하지 않는다. 다음 초에는 다시 추출하므로 같은 학생이 재선정될 수 있다. 정수가 아닌 표본 크기는 구현안으로 `min(N_g, max(1, floor((N_g + 5) / 10)))`을 사용한다. 이 식은 10%를 사사오입한다.
3. 각 등급에서 뽑힌 원점수의 평균 `sampleMean_g`을 계산한다. 등급별 추출 인원 비중이 아니라 **전체 응시자에서 해당 등급이 차지하는 비중**으로 가중한다. 모집단이 0명이면 지수는 `null`이다.
4. 결과에는 `sampledAt = t`, `publishAt = t + 30분`을 저장한다. 예를 들어 KST 15:00:00 계산값은 15:30:00, 15:00:01 계산값은 15:30:01에 공개한다. 브라우저에는 공개 시각이 지난 결과만 전송하고 계산 시각과 ‘30분 지연’을 표시한다.

```text
sampleAverage = Σ(N_g × sampleMean_g) / Σ(N_g)
Sample MPI    = sampleAverage × 10
```

등급 A의 유효 응시자가 100명이고 표본 10명의 평균이 80점, 등급 B가 500명이고 표본 50명의 평균이 60점이라면 표본 가중 평균은 `(100 × 80 + 500 × 60) / 600 = 63.333…`점이다. Sample MPI는 약 633.33이다. 소수 등급이 5명이면 1명을 뽑으며 가중치의 분자는 해당 등급 전체 인원인 5다.

### 서버 작업과 지연 처리

- 시험 제출 API와 샘플러를 분리한다. 데모에서는 활성 주간 회차의 유효 응시 행에서 원점수와 응시 전 MMR 등급만 읽어 매초 표본을 추출한다. 사전 등급은 Arena의 MMR 기준으로 응시 시작 시 저장하며, 기존 기록이나 초기 MMR 1,000은 7등급을 사용한다.
- `(marketId, sampledAt)` 고유 키와 lease로 초당 결과를 한 번만 저장한다. 재시도는 이미 저장된 표본을 유지한다. 초 단위 표본은 14일간 보관하며, 응시자별 성적·샘플 ID·미공개 지수는 공개 응답에 포함하지 않는다.
- 화면이 열려 있을 때 1초마다 서버가 공개 시각을 지난 최근 표본과 체결 데이터를 반환한다. 연결이 끊겼다 돌아오면 최신 스냅샷을 다시 읽는다. 장애로 생성하지 못한 초에는 표본 공백을 남긴다. 마지막 30분의 응시는 마감 전 공개 지수에 안 보일 수 있으나 유효하면 최종 정산에 포함한다.
- 최종 정산은 별도 원본 대사로 계산한다. `Settlement MPI = 10 × (유효 응시 원점수 합계 / 유효 응시자 수)`다. 모집단 0명은 ‘정산값 없음’으로 처리하며 가상의 지수 0을 만들지 않는다.

## 4. 선물 호가·체결·청산

1계약은 **MPI 1포인트 차이당 1TP**다. 학생은 최우선 매수·매도 호가, 남은 시간, 보유·가용 TP와 공개된 지수를 확인하고 가격과 수량을 입력한다. 신규 **LONG은 매수**, 신규 **SHORT는 매도**다. 중도 청산은 기존 LONG의 매도 또는 기존 SHORT의 매수로 접수한다.

- 지정가 주문은 매수 최고가·매도 최저가가 먼저다. 같은 가격이면 서버가 확정한 접수 순번이 빠른 주문부터 처리한다. 매수 지정가가 매도 지정가 이상일 때 수량이 겹치는 만큼 체결한다. 서로 조건이 맞으면 먼저 대기한 주문의 가격을 적용하는 구현안이다. 미체결 잔량은 호가창에 남고 학생이 취소할 수 있다.
- 보유 한도는 **시장당 최대 5계약**이다. 신규 주문의 미체결 잔량도 잠재 보유량에 반영해 동시 체결로 한도를 넘지 않게 한다. 기존 방향을 닫고 반대 방향으로 전환할 수 있다. 청산 주문은 보유 수량만 예약하며, 반대 주문과 체결된 부분만 종료된다.
- 학생에게 주문 직전 방향·지정가·수량·필요 TP·최대 손실을 표시한다. 예를 들어 640에 SHORT 2계약을 열면 필요 TP와 최대 손실은 720TP다. 최종 MPI가 600이면 +80TP이고, 700이면 −120TP다.
- 주문·취소에는 명령 ID를 사용한다. 같은 요청을 재시도하면 기존 결과를 반환한다. 체결·취소·마감은 시장 문서를 조건부 갱신해 순서를 정하고 주문·체결·포지션·담보 변경을 한 MongoDB 트랜잭션에서 확정한다. 체결 작업이 마감 직전 경합으로 재시도되면 서버 시각을 다시 검사한다. 자기 주문끼리 체결할 수 없고, 취소와 체결이 동시에 들어오면 먼저 반영한 수량을 기준으로 남은 수량만 처리한다.

### 완전담보와 TP

신규 Exchange 학생에게 **2,000TP를 최초 한 번** 지급한다. 주간 초기화 없이 확정 잔액을 다음 주에 이월한다. TP는 무료 비환금성 게임 포인트이며 현금·Pro 크레딧과 분리한다. PDF의 무료 운영 범위를 따른다. PPT가 유료 TP 구매는 미정으로 표시한다.

주간·실제 모의고사·수능 시장은 계정의 TP 지갑을 공유한다. 같은 날 여러 시장에 주문하면 공통 가용 잔액을 원자적으로 차감하고 시장별로 담보를 예약해 같은 TP가 중복으로 쓰이는 것을 막는다.

| 항목 | LONG | SHORT |
| --- | --- | --- |
| 진입가격 `P`의 계약 1개에 필요한 담보 | `P` TP | `1000 - P` TP |
| 만기 Settlement MPI가 `S`일 때 지급액 | `S` TP | `1000 - S` TP |
| 만기 순손익 | `(S - P) × 수량` | `(P - S) × 수량` |
| 조기 청산가격이 `C`일 때 순손익 | `(C - P) × 청산 수량` | `(P - C) × 청산 수량` |

신규 지정가 주문은 지정가 기준 최대 필요 TP를 예약한다. 체결 시 실제 체결가 기준 담보를 떼어 두고 차액을 가용 TP로 반환한다. 640에 LONG 1개와 SHORT 1개가 체결되면 담보 640TP와 360TP를 합쳐 1,000TP를 보관한다. 최종 MPI가 700이면 LONG에 700TP, SHORT에 300TP를 지급하므로 순손익은 +60TP와 −60TP다.

### 중도 청산의 자금 이동

- **양쪽 신규 진입**이면 LONG·SHORT가 함께 생기고 시장 보관 담보가 계약당 1,000TP 증가한다.
- **한쪽 청산·같은 방향 신규 진입**이면 신규 보유자의 담보가 기존 보유자에게 이전되어 해당 청산 손익을 확정한다. 예를 들어 A가 LONG을 640에 열고 C가 새 LONG을 680에 받아 가면 A에게 680TP가 지급돼 +40TP다. C의 진입 기준은 680이며 기존 상대 SHORT는 유지된다. 전체 시장의 계약 쌍과 보관 담보는 유지된다.
- **양쪽 청산**이면 청산가격을 기준으로 LONG에 `C`, SHORT에 `1000 - C`를 시장 보관 담보에서 지급하고, 미결제 계약 쌍을 하나 줄인다.
- 구현안으로 주문 가격은 1 MPI 단위, 정산 지수와 TP는 소수 둘째 자리 고정 정밀도로 저장한다. 최종 지수를 한 번 반올림한 다음 보완 지급액을 같은 값에서 계산해 계약 쌍의 합계를 1,000TP로 맞춘다. 정상 거래 중에는 열린 LONG·SHORT 수량이 같고, 보관 담보가 열린 계약 쌍 수 × 1,000TP인지 대사한다.

## 5. 캔들, 거래량과 이동평균선

PPT 23–26장의 차트는 **실제로 체결된 선물 가격**을 사용한다. 공개 Sample MPI는 시간 지연이 표시된 별도 선으로 겹쳐 보거나 숨길 수 있게 한다. 차트 축과 툴팁에서 선물 체결가와 표본 지수의 범례를 구분한다.

| 값 | 해당 구간에서 계산하는 기준 |
| --- | --- |
| 시가 O | 첫 체결 가격 |
| 고가 H | 가장 높은 체결 가격 |
| 저가 L | 가장 낮은 체결 가격 |
| 종가 C | 마지막 체결 가격 |
| 거래량 | 체결된 계약 수의 합. 한 체결을 양쪽에서 두 번 세지 않음 |
| MA 5 / MA 10 | 체결로 형성된 최근 5개 / 10개 확정 캔들의 종가 단순 평균 |

예를 들어 640 → 651 → 635 → 655 → 650 순으로 실제 체결되면 O/H/L/C는 **640 / 655 / 635 / 650**이다. 진행 중인 캔들은 새 체결에 맞춰 종가·고가·저가를 갱신한다. 구간에 체결이 없으면 빈 구간을 표시하고 최근 체결가는 마지막 값과 시각을 유지한다. 상승은 청록, 하락은 분홍을 사용하고 가격·방향 표시도 함께 제공한다. MVP는 캔들·거래량·이동평균선을 제공하고 RSI·MACD 등은 후속 검토로 둔다. 차트 시간 단위는 구현 기본값으로 1분·5분·1시간을 제공한다.

## 6. 선물 주문 화면의 배점별 계산기

맵쓰 주간 모의고사는 해당 회차의 공식 배점 데이터 `points`에서 2점·3점·4점 문항 수를 집계한다. 실제 시험은 회차별 배점 구성이 확인되면 같은 계산기에 적용한다. 주문 화면에서 각 배점의 총 문항 수와 가정한 정답 수, 해당 행의 예상 점수를 입력·확인할 수 있다. 시험의 문제별 정답이나 실제 그룹별 정답률은 노출하지 않는다.

| 배점 | 시험 문항 수 예시 | 예상 평균 정답 수 예시 | 평균 점수 기여 |
| --- | ---: | ---: | ---: |
| 2점 | 3 | 2.5 | 5.0점 |
| 3점 | 14 | 9.5 | 28.5점 |
| 4점 | 13 | 7.5 | 30.0점 |
| 합계 | 30 | 19.5 | **63.5점 → 예상 MPI 635** |

```text
예상 평균 원점수 = 2 × n2 + 3 × n3 + 4 × n4
예상 MPI        = 예상 평균 원점수 × 10
```

- 평균 예측 모드의 `n2`, `n3`, `n4`는 응시자 한 명당 평균 몇 문항을 맞힐지에 대한 가정이다. 소수를 허용한다. 예시 응시자 한 명의 정답 개수를 입력할 때는 정수로 입력해 그 조합의 원점수를 계산할 수 있다.
- 입력 범위는 배점별 `0 ≤ 예상 정답 수 ≤ 그 배점 문항 수`다. 구성은 회차에서 읽어 실제 총점 100과 일치하는지 검증한다. 예시의 3·14·13은 화면 동작을 설명하는 수치다.
- 입력이 바뀌면 주문 옆에 예상 평균과 예상 MPI를 즉시 표시한다. 사용자가 입력한 예상 MPI와 최근 체결가를 비교할 수 있게 한다. 계산값은 개인 입력에 따라 달라지며 실제 Sample MPI·호가·주문에는 영향을 주지 않는다.

## 7. 만기, 검증과 시장 취소

1. 맵쓰 주간 시장은 토요일 12:00에, 실제 모의고사·수능 시장은 운영자가 지정한 종료 일시에 마감한다. 신규·청산 주문의 미체결 잔량을 취소해 예약 TP나 청산 예약 수량을 되돌린다. 이미 체결된 포지션은 정산 대기로 옮긴다.
2. 맵쓰 주간 시험은 `settlementCompletedAt` 등 기존 마감 후처리 완료 상태를 확인한다. 마감 전에 정상 접수한 답안, 확정된 정정, 부정행위 판정과 데모 제외를 대사한다. 시장이 참조하는 유효 응시 수, 원점수 합계와 정산값을 기록한다. 집계가 아직 완료되지 않았으면 학생에게 ‘성적 검증 중’을 표시한다. 실제 시험의 정산은 아래 절차를 적용한다.
3. 정상 확정이면 각 열린 계약에 Settlement MPI를 적용한다. 포지션 종료·담보 지급·지갑 갱신을 같은 트랜잭션에서 처리하고 고유한 정산 원장 키를 사용한다. 중단 뒤에는 미처리 계약부터 재개한다. 취소와 정산은 동일 시장에서 서로 배타적인 최종 결정으로 저장한다.
4. 시험 취소, 성적 원본 손실 등으로 유효 평균을 확정할 수 없을 때는 시장 무효 상태를 표시한다. PPT에 개장 이후 무효 처리의 세부 규칙은 없으므로, 구현안으로 해당 시장의 거래 영향을 되돌리고 사용자별 시장에 배정한 TP를 원상 복구한다. 이를 위해 해당 시장에서 확정된 중도 청산 손익은 같은 시장 안에서 사용할 수 있게 하되, 정상 정산이 끝날 때 전체 지갑의 다음 시장 가용 잔액에 편입한다. 사용자별 시작 배정액과 장부를 남겨 이미 청산한 계약이 있어도 무효 때 일관되게 복구한다.
5. 맵쓰 시험의 본인 성적·해설은 기존 정책에 따라 공개한다. 시장 결과에서는 확인 가능한 시험 복기 자료와 함께 평균 원점수·Settlement MPI·예측과 손익을 보여준다. 확정 TP를 이월하고, 간단한 순위에는 공개 동의한 닉네임과 정상 확정 순손익을 사용한다.

### 실제 시험의 성적 발표 대기

실제 모의고사·수능에도 **수학 평균 원점수 × 10**을 정산 지수로 적용한다. 일정 등록 때 성적 출처와 모집단을 입력할 수 있다. 거래가 끝나도 평균 점수가 아직 발표되지 않았으면 시장에 **성적 발표 대기**를 표시하고, 이미 체결된 포지션은 해당 회차의 정산값을 확인할 때까지 보관한다.

운영자가 회차에 대응하는 성적 출처, 모집단, 발표 링크·시각과 평균 원점수를 확인해 정산값을 등록하면 TP 정산 작업을 실행한다. 데모는 이 운영자 등록으로 외부 시험을 정산한다. 평균 원점수가 공개되는 출처와 집계 범위는 실제 시험 유형별로 확정한다.

## 9. 구현 순서와 인수 기준

| 단계 | 개발 작업 | 인수 기준 |

| 3. 호가·체결·캔들 | 주문과 취소, 가격·시간 우선 매칭, 담보, 실제 체결 차트 | 반대 주문 없으면 체결 없음. 부분 체결, 가격 개선 차액 반환, 자기 체결 차단, 5계약 한도, 첫 체결과 OHLC 예시 일치 |

격리 MongoDB replica set에서 주문·취소·마감 경쟁, 담보의 합계, 청산과 시장 무효, 복구 중 중복 체결을 검증한다. 스테이징에서는 141시간 동안 생성되는 최대 507,600개 초 단위 표본의 저장·공개 지연을 확인하고, 거래 차트가 새 표본 값만으로 바뀌지 않는지 확인한다. 운영 효과는 모의고사 완료율, 다음 회차 재응시율, 해설 복기율과 요일별 체결·미체결 비율로 본다.

데모 회귀 검증은 `node audit/runMemoryMongoSuite.js audit/verifyExchangeDemoDb.js audit/verifyWeeklyMockWindowDb.js`로 실행한다. 시험과 파일이 없을 때의 미개설, 관리자 권한, 고3 수능 예약, 정규 회차 제출 자격, 표본 지연, 지정가 체결·청산·정산과 TP 반환을 확인한다.

세부 설정 중 **MMR 등급 경계와 미배치 적용값, 표본 반올림, 주문 가격 단위·정산 정밀도, 개장 후 시험 무효 복구 방식, 실제 시험별 평균 원점수 출처**는 원문이 정하지 않은 구현 항목이다. 위 기본안을 시장 규칙 버전으로 기록해 검증한다. PPT의 등급컷 옵션형 상품은 별도 기획 항목이다.
